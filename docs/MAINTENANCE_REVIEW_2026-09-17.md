# 2026-09-17 维护性梳理

## 范围和依据

按 Ponytail 的原则，先核对运行入口、调用关系、数据边界，再删除或合并。扫描主仓库 544 个 JS/TS 源文件和剧本大师 234 个前端文件，并核查 Python 后端、部署脚本和自动化测试。静态扫描只提供候选，删除以实际调用核查为准。

主站：React 创作端 / 管理端 → Fastify 路由和权限 → 业务 Service / Repository → Postgres；生成任务经积分预留、队列、Worker、Provider、媒体存储，最终回写资产和分镜。Redis 承担队列，JSON 保留开发兼容和媒体缓存。

剧本大师：Next.js → 独立 FastAPI → 创意 / 设定 / 规划 / 剧集生成 / 审查修订 → 工作区与版本持久化。主站登录票据建立身份，交接接口导入剧集、分镜与资产建议。保留独立服务与部署边界，不复制其生成流程到主站。

## 已核实的清理位置

- 主站旧小说导入 / 开发面板、一句成片弹窗和长剧本占位页没有运行入口；配套专用样式及前端请求包装可以删除。后端小说、Agent 和实验接口仍有调用与兼容价值，保留数据与测试。
- 审计日志在已有公共实现之外重复了三份；统一使用 `core/audit/auditLog`，保留调用方事务。
- 任务恢复重复声明数据库行、列和转换；统一到现有 `generation/repositoryData`。
- 生成模块再次实现项目 / 资产 / 镜头数据库转换；复用项目模块，并保留镜头所属剧集字段。
- AI 任务与媒体任务重复读取、锁定积分来源；共用同一账单目标查询，保留组织过滤、行锁和扣款幂等。
- 前端已存在任务索引，但资产缩略图与连续视频仍重复遍历全量队列；共用索引，保留活动任务、回退版本、尾帧的选择规则。
- 剧本大师重复规划会话转换、导出时长计算及无人调用的旧导航与质量循环客户端；使用现有模块收敛。

## 全量回归发现并修复的问题

- 多个请求同时归档同一素材时，存储键的唯一约束会冲突；导入插入现在同时处理主键和存储键冲突，回归验证重复归档不会增加条目或孤立版本。
- 资产提取会因相邻人物 / 动物的描写污染主体类型；仅根据当前角色名称和清单判定，并覆盖明确动物和人物携带动物的用例。
- 汇总已保存剧集时，超长段落的末尾可能被采样遗漏；保留段落首尾，再按已有分布策略采样。
- 剧本大师连接超时可能在累计时限前极短时间返回，造成错误类型不一致；按实际限制该请求的预算判定超时，覆盖读取、连接、TLS 与更短的普通请求时限。
- Windows 的 UTF-8、子进程系统变量、Git Bash 路径和跨平台报告路径导致部分验证流程不能运行；修复测试和探针的移植性，保留凭证环境隔离。

## 验证缺口

旧 `test:full:stable` 只运行显式列出的 API 单元 / 集成文件，遗漏 legacy、HTTP 契约、安全及其他模块。改为发现并执行全部 API 测试；同一检查再覆盖浏览器回归。

隔离测试环境使用独立 Postgres / Redis，禁止访问生产业务数据库。历史 migration 保持不变。完整检查通过后才备份、部署和推送；真实付费模型调用不属于本次自动化验证。

Postgres 测试 fixture 改用独立临时数据库，避免历史 migration 中未限定 schema 的约束查询互相干扰。配置外部测试 Postgres 时，测试用户需具备 `CREATEDB` 权限；测试结束删除的仅是本次 fixture 创建的随机命名数据库。浏览器回归使用 Playwright 安装的浏览器，移除特定电脑路径并限制同时运行数量。

## 不变量

组织隔离、登录权限、积分审计、任务幂等 / 退款 / 恢复、历史任务输出和数据库 migration 均保留。关闭的 UI 不代表可以删掉历史数据或服务。外部 Provider、支付和登录占位的开放程度不在本次重构中改变。
