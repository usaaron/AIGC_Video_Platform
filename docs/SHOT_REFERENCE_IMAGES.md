# 分镜多张参考图

编辑镜头支持一次上传多张图片，也可从项目参考图或账号资产库追加。左侧大图预览与缩略图按图1、图2排序；右侧“本镜头资产 → 参考图”点击后在光标处插入 `【图N】`。用户可在编号后描述人物、服装、构图等用途。

插入后，参考图按钮加深为琥珀色并显示“已引用”，正文中有效的 `【图N】` 同色高亮；提示词模板继续使用深绿色。标记随正文和参考图列表变化实时更新，不改变保存的纯文本及视频参数。

- 单镜最多保存 9 张参考图；连续生成需给前镜尾帧预留一位，最多使用 8 张。超量或悬空编号在提交前阻止，不创建依赖任务或扣积分。
- 移除图片会同时移除正文中对应的编号，后续图片编号及提示词引用同步前移。上传部分失败时保留成功项，可继续补传。
- `Shot.referenceImages` 是有序的 `{ url, name? }[]`，与生成封面 `imageUrl` 分离。空数组表示清空；未提供字段的旧数据才使用旧手动封面作为单张参考图。生成封面不自动充当新参考图。
- migration `044_shot_reference_images.sql` 增加可空 JSONB 字段；所有分镜创建、更新、批量插入、历史导入和生成上下文读取均保存此字段。
- API 从保存的分镜、项目资产构造图片序列，忽略客户端传来的图片映射。`manualReferenceImages` 和 `sourceShotSnapshot` 保存提交时的顺序；排队后编辑不改变此任务。
- 输入顺序为：前镜尾帧（连续模式时）、用户明确选择的图片、自动匹配的资产身份图、资产外观图。自动图片只填剩余位置；显式图片不能静默裁剪。
- 提示词编译器 v17 沿用 v16 的编号映射：连续模式下把用户 `【图1】` 转为 Provider 的 `【图2】`，其余依次偏移。原始提示词不变；自定义图片用途和完整动作保留。
- Worker 保留明确选择的全身/服装图片，只转换自动身份图的 `asset://` 引用。上传媒体按项目和组织解析；缺失/越权图片导致任务失败，不能跳过后继续改变编号。批量复用视频比较参考图 URL 和顺序。历史版本“用此版提示词编辑”同时载入该任务的参考图，保存前不修改当前镜头或切换视频版本。

回归覆盖：契约、提示词编号、Postgres 保存/重读/清空、API 快照、Worker 到 Dora 请求体顺序、尾帧偏移、服装图保留、越权源拒绝、视频复用失效，以及 1440/390 宽度编辑操作。Provider 使用测试替身，不消耗真实生成额度；第三方模型对参考图的实际视觉遵循程度仍取决于模型效果。

## 分镜提示词精简（2026-09-17，已部署 `123a7fd`）

新分镜以换行区分场景、角色、动作、对白和已有的机位/构图/光影/声音。不填“角色完成当前可见行动”等缺省描述，不把同一动作重复放入剧情、镜头任务、导演节拍。显式的运镜优先于默认推断；镜头首尾状态只在有来源且未重复动作时补充。每镜仍沿现有剧本拆分规则生成，没有新增文本模型调用。

旧自动分镜通过共享 `cleanStoryboardPrompt` 清理已知系统模板。没有旧模板标记的用户文本不重写；未知字段、自由文本、原文对白及图片编号保留。卡片、编辑器和视频编译器使用相同函数，编辑后保存才回写分镜；历史生成快照不批量改写。

`seedance-storyboard-v17` 在完整分镜正文外，仅补充时长/比例/项目风格、必要的图片编号、接镜方式、参考资产身份和简短声音要求。不再重复主动作、追加固定运镜、要求每几秒表情变化，或从“头发/衣服/雨伞”等词推断风雨。显式时间轴与多项连续动作不截断；图片参考身份说明不再重复资产长描述、图片生成提示词或内部属性键值。

接镜由真实图片和任务依赖执行。连续镜头仅说明“以图1（上一镜尾帧）作为开场，继续本镜动作”；独立镜头不携带前镜图片。旧的整段“上一镜终态/本镜动作起点”回顾只保留可辨认的显式开场状态，自定义衔接备注保留。不会把上一场完整动作或当前场次结局放进本镜开场，也不从上一段字符串尾部截出半句话。
