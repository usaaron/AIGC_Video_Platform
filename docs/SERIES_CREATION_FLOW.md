## 2026-09-20 结构化交接与人物资料复用（本地实现，当前）

- 人物资料扫描在单次请求内建立索引，按人物复用外观片段及年龄结果；仍保留原有首个列表片段与明确设定优先规则，不在全局缓存整份用户正文。快速分析和显式模型分析都复用已解析的候选及设定；模型提示仅取有限长度的视觉事实，不新增模型调用。
- v2 导入的每集正文新增可选 `assetEvidence`，版本为 `script_asset_evidence.v1`，包含最终正文 SHA-256、各资产类的完整性标志、显式名称/事实及来源场次。发送方仅从已保存正文的场次清单收集证据，解析已知人物 ID/别名，只用人物外观作为视觉事实；不从普通叙述或全剧人物库补猜出场人物。明确仅声音/旁白排除，具名 VO/OS 标记归一化；未知内部人物 ID 不成为名字并使人物类标记为不完整。
- 明确空数组表示该类已确认无资产，缺少字段或无法解析的引用表示仍需补查。交付前校验准备内容，证据超限或来源变化时省略证据、保留正文交付并提示。最多 2,000 条、序列化 UTF-8 500,000 字节；内部准备字段不进入请求。证据纳入交付幂等摘要。`scriptsOnly` 仍不自动创建资产、分镜、任务或读取分镜。
- 主站对收到的证据验证 schema 与正文哈希，哈希不符拒绝整个导入，不部分写入。使用现有 `continuityState.scriptAssetEvidence` JSONB，无数据库迁移。仅证据变化时更新剧集修订，保留草稿、状态、总结、其他 continuity 字段以及已有镜头/媒体。旧客户端不带证据时清除旧证据；JSONB 对象键序变化不会造成虚假修订。
- 资产源缓存版本为 `script-asset-source.v2`，缓存键包含证据摘要。每次使用前验证正文哈希；主站手工改正文后旧证据失效，回到当前正文提取。完整类别直接使用显式依据并跳过该类文本字段扫描；不完整类别合并正文候选。只有所有来源都完整时，模型输出才受该类显式名单限制，不能重新添加名单外资产或把明确为空的人物补回。明确设定优先于冲突的模型性别、年龄等事实。
- 前端自动分析范围和手动分析任务指纹同时纳入已保存证据；仅外观资料变化也重新提取，JSONB 键序或无关 metadata 变化不重扫。切集、未保存编辑和旧请求保护沿用上一轮逻辑。
- 同一合成基准（24 集、73,623 字符；内存 ProjectService；预热 3 次、每场景 15 次）相比上一轮：首次分析中位值 196.67 → 13.39 ms；不变重复分析 178.62 → 2.36 ms；仅改一集 179.36 → 2.65 ms。不含网络、数据库或模型耗时，不能外推为完整创作流程加速。

## 2026-09-20 第一轮规则提取与按集复用（历史基础，后续更新见上节）

## 主项目快速剧本本地候选（2026-09-20）

主项目新中文作品默认「故事梗概 → 创作安排 → 剧本正文」，作者只需确认梗概和一次完整的创作安排。人物与逐集逐场安排一次生成，正文按集顺序写作，先保存再检查；不要求快速作品完成长总纲或递归故事树。每集局部修复最多一次，重大歧义或未解决问题暂停后续依赖；作者修改既有正文后，后续检查失效但原稿保留。

没有快速模式标记的旧项目保留原有流程，无正文的大陆项目可主动进入快速创作。独立剧本大师和海外标准流程继续使用原工作台。快速版首版限中文一万有效正文字以内，默认8集约8千字；海外双语快速创作不在此次范围内。

最后明确交付已保存正文，继续主站「资产 → 分镜」；仍复用 v2 交接、正文哈希和结构化资产依据。页面驱动连续生成，暂停或关闭后保留当前进度，重新打开需要主动继续。仅本地测试替身验收，不等同真实模型或生产端全流程验收；尚未推送、部署。支持仓库说明：`script-master-update/deploy/QUICK_SCRIPT_2026-09-20.md`。

## 同日补充：已有分镜后的返修与中断恢复

已交付剧本产生分镜后，作者修改并保存正文，重新检查后交付。普通同步仍先保护旧制作内容，交付弹窗提供「保存修订并更新分镜」，由作者明确确认后继续原项目和原剧集，不需要另建项目。

- 将修改集的旧标题、正文、完整镜头和媒体/任务关联写入 `continuityState.scriptProductionHistory`。标题单独修改保留原镜头；正文修改由现有确定性解析器重建对应分镜，不调用模型或扣积分。
- 只有来源正文及生成字段均明确匹配的镜头才复用；承接镜头还需保留原前驱。手工调整或存在歧义的镜头会重新建立，旧制作内容仍在历史中。未修改剧集保留。
- 旧镜头退出当前制作列表，任务和媒体文件保留。分镜页折叠显示「制作修订历史」，可以查看旧正文、镜头、原参考图及可用媒体；暂不提供整版一键恢复。
- 契约只在纯正文交付时允许 `storyboardRevision: preserve-history`。快照、正文、镜头变更和回执同一事务提交；生成任务使用同一项目锁，在扣费/写入前重新校验镜头及请求版本，避免返修期间对失效镜头创建新任务。幂等重复请求返回同一结果。
- 中断后先只读查询保存结果，显示保存/检查集数、当前步骤、最后保存时间和保护倒计时，可手动刷新。已确认结束的请求及时恢复界面；结果仍未知时最多保护20分钟，过期恢复仅恢复状态，后续生成仍需明确继续。关闭浏览器不在后台自动续写。
