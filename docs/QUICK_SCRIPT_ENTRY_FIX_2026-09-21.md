# 新网剧误入标准剧本流程修复

主站新建网剧表单原来固定提交每集 60 秒，而配套剧本快速版只接受 75–115 秒。宿主启动接口传递该时长后，剧本前端按不兼容时长创建标准项目，所以用户在主站新建网剧也会看到「故事设定 → 分集大纲 → 剧本正文」。这属于两个入口默认值未对齐。

本次将主站新建网剧的默认每集时长改为 90 秒，与快速版默认一致。广告和短片仍为 30 秒；已有项目及作者自定义时长不修改，独立剧本大师、海外项目和已有标准流程继续沿用原入口。

对于已经创建且没有正文的大陆项目，用户可以显式点击「快速创作」。该入口沿用已有故事梗概，以 8 集、每集 90 秒、总正文约 8000 字初始化快速创作；配套剧本前端在梗概确认前显示这个篇幅。仅打开入口不会修改存储中的旧项目。

验证：主站新建表单与剧本嵌入相关 8 项测试通过，Web lint 和生产构建通过；配套剧本快速入口、恢复和编辑相关 30 项测试、TypeScript 检查通过。新增回归覆盖网剧创建时长、广告/短片选择，以及已有 60 秒项目进入快速版后保留梗概和原存储对象。

标准流程中模型返回后无法保存的问题已在真实 PostgreSQL 16 与线上驱动组合下复现：生成检查点的 INSERT 返回 `rowcount=-1`，原逻辑误判为写入冲突并回滚。配套剧本服务改用 `RETURNING` 返回的主键确认写入，保留真实并发冲突检查。该回归不调用模型；不能用入口或存储回归代替真实模型质量验收。
