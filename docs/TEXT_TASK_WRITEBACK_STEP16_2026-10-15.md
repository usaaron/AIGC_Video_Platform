# 文本任务执行与写回保护第十六步

## 范围

本步为主站 `text/text` 任务补齐执行身份、正文/分集写入、运行时持久化与退款边界，是后续文本完成回执的前置工作。独立 Script Master 仓库不在本次范围内。

文本流程既可能实际调用 Provider，也可能保留长原文、使用本地快速资产建议、丢弃过短输出或跨多集调用；现有计时回调不能证明最终正文确实来自同一次 Provider 响应。因此本步没有签发文本完成回执，没有把文本纳入正式交付下载。

## 执行与正文写入

- 领取任务后冻结组织、项目、用户、任务、请求键、attempt、原 worker 租约、操作和模型。取消、过期、接管或重试后的旧执行不得写正文、分集草稿、流式预览或终态。心跳只续期原执行，不能取得新租约的权限。
- 主站生成、扩写及分集调用传播同一私有执行上下文。直接请求原有参数位置保持兼容。缺失或非法操作字段仍进入处理器正常失败路径并处理退款，不会因提前捕获执行身份而卡在 running。
- PostgreSQL 正文和分集事务先锁任务，再锁目标内容，并在锁等待后、实际写入前后检查租约到期。JSON 兼容路径在同次 mutation 内校验。
- 正文/剧集提交后的缓存镜像比较完整旧快照，保留同时间戳的并发编辑、删除及新任务结果；父项目已删除时不会插回孤立剧集。发生任何相关并发改变便保守跳过镜像，数据库保持权威，缓存由后续常规刷新同步。

## 任务持久化与统计

- Worker 的运行时快照绑定原租约；领取、恢复和维护使用原数据库快照的条件更新。私有上下文绑定完整规范化快照摘要，带时限与容量限制，不能由请求 metadata 提供。
- 无私有上下文的文本写入仅允许生命周期内容不变的幂等更新。数据库拒绝旧快照后，只有缓存仍等于该次送出值时才恢复权威任务，保留之后的并发编辑。
- 文本预览仅捕获一次 running 快照并走同一持久化规则。队列先持久化领取，再调度处理器；同一毫秒内的状态变化也纳入待写任务 ID。
- 文本完成/失败进入缓存时立即标记终态统计和通用任务退款待提交。成功提交或权威状态恢复之后才核对是否结算；持久化失败、旧执行被拒或缓存发生并发修改均不能提前统计成功或执行通用任务退款。直接计费/分集预约退款遵循下一节的事务规则。
- 退款 metadata 仅修改与已退款快照一致的任务，并为该字段登记控制写入上下文，避免异步退款误捕获并发生成结果。

## 退款边界

- 携带队列执行 guard 的单次正文 direct 计费与分集预约退款，在账本事务内检查原执行身份和预约引用；等待账户锁后再次检查租约。拒绝旧 attempt、接管租约、跨范围及不属于当前操作/剧集的引用。无 guard 的 HTTP 直接请求保持原计费路径。
- 预约退款可在任务 failed 终态提交前发生：Provider 或写入失败后，账本事务核验原 running 租约或已持久化的取消执行凭据，完成退款；随后队列处理器才提交失败终态。该规则与通用任务退款的提交后时序分别验证。
- 普通取消及新文本任务自动替换旧任务时，在释放原租约之前记录不可逆执行摘要。该凭据只允许被取消的原执行退款，不含原租约凭据，也不能借用同 attempt 后继执行的取消状态。
- 禁止退款停止仍遵守 `creditsRefundDisabledAt`。分集取消仅退未完成集，已完成集保留扣费；分集任务本身不依赖通用任务估算积分补退。
- 创建任务会移除外部提供的取消执行凭据。
