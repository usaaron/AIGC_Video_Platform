# 代码规范

## 基本原则

- 优先写清晰、可删除的代码，不为假设中的未来需求建立抽象。
- 单一业务规则只保留一份；常量、状态机和计费逻辑不得散落在页面中。
- 组件负责展示与交互，领域函数负责计算，服务模块负责外部 I/O。
- 密钥、会员权限、积分余额和并发限制必须由服务端校验。

## React

- 使用函数组件和 Hook；组件名使用 PascalCase，Hook 使用 `use` 前缀。
- Web 页面组件放在 `apps/web/src/pages/`，跨页面复用后再移动到 `components/`。
- 不默认使用 `useMemo` 或 `useCallback`；只有性能测量或稳定引用契约需要时才添加。
- 派生数据直接计算，不用 Effect 同步两份状态。
- Effect 必须清理计时器、订阅和事件监听。
- 列表使用稳定业务 ID，禁止使用数组索引作为可变列表的 key。

## JavaScript

- 使用 `const`，只在确实需要重新赋值时使用 `let`，不使用 `var`。
- 领域逻辑优先写成纯函数，并覆盖正常、边界和失败路径测试。
- 异步错误必须进入可观察状态，禁止空 `catch`。
- 不直接修改参数、Props 或 State；使用不可变更新。
- 文件默认不超过 300 行；超过时先按职责拆分，而不是按代码长度机械拆分。

## 后端 TypeScript

- Route 只做输入校验、权限声明和 HTTP 映射，不直接访问数据库。
- Service 编排领域操作，只依赖接口；Repository 和外部 Provider 实现接口。
- 所有外部输入使用 `@seqora/contracts` 中的 Zod Schema 校验。
- 数据查询必须显式携带认证主体或租户范围。
- 管理接口放在 `modules/admin`，并逐个声明权限，不使用统一的“是否管理员”布尔值。

## 样式与交互

- 复用 `index.css` 中的设计令牌，禁止在组件中散落主题色。
- 所有图标按钮必须有 `aria-label` 或可见文本。
- 固定格式元素应有稳定尺寸，避免加载状态造成布局跳动。
- UI 变更至少验证 1440px 桌面和 390px 移动端，不允许横向溢出和文字遮挡。

## 命名

- 事件 Props 使用 `onXxx`，内部处理函数使用 `handleXxx`。
- 布尔值使用 `is`、`has`、`can` 或明确状态名。
- API 模型与 UI 展示模型不混用；适配转换放在 `services/` 或对应 `features/`。

## 自动化

Prettier 是格式唯一来源，Oxlint 负责静态规则，Vitest 负责单元测试。不要手工争论可由工具确定的格式。提交前运行 `pnpm check`。
