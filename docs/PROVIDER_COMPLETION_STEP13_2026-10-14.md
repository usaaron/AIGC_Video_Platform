## 本轮实现

新增 `seqora.provider-completion.v1` 契约。`metadata.providerCompletionReceipt` 记录的是 **服务端观察到远端完成，并成功保存本次主视频媒体**，不是 Provider 数字签名，也不代表内容、物理或连续性验收通过。

- 只覆盖新完成的远端 Seedance 视频，适配器限定 DoraRouter、StringX 和 Volc Ark。图片、文本、本地整集合成、旧任务回填不在本步范围内。
- 回执绑定组织、项目、任务、实际适配器、远端任务 ID、生成 attempt、完成时间、当前媒体版本，以及主视频的存储键、大小、类型和 SHA-256。人工验收、冻结合同或下载推进任务更新时间，不会单独使原回执失效。
- 远端必须明确返回 `completed`，本轮取得完整主媒体并成功写入对象存储，才能签发回执。提交成功、运行中、URL、旧缓存描述或下载失败都不构成完成证明。服务端进程以同次入库描述对象及轮询身份校验来源，复制或篡改描述不能补签。
- 主媒体要求 HTTP 200、无分段响应、非空、声明大小一致、MP4 类型和基本 `ftyp` 签名。读取含等待响应头最多 15 秒、100 MiB；超时和异常销毁流，迟到响应同样清理。基础签名验证不等于视频解码或画面质量验收。
- 新远端主媒体和尾帧以任务、attempt 和内容哈希命名，旧 worker 迟到写入不同字节不会覆盖当前结果；主媒体与尾帧持久化各增加 30 秒整体等待上限，迟到结果不签发完成回执。尾帧可能由适配器本地提取，回执不宣称它是上游原生输出，也不证明它来自同一份主视频字节。
- 轮询结果应用时比较组织、项目、任务、Provider、远端 ID、attempt 和原 worker 租约；不匹配时拒绝应用。重新提交、重试及无本次完成证据的写回会清除运行任务的旧回执。

## 数据库与来源边界

完成回执首次写入 PostgreSQL 时，必须仍为同一 `running` 任务、attempt、Provider ID/适配器及原 lease owner/token。原租约只存进程内部的短时上下文，不写入回执或 metadata；最多 1,024 项、5 分钟，丢失或过期时拒绝首次写入。上下文以完整回执摘要关联，因此任务经过结构化复制仍可校验。事务回滚保留上下文以便重试，提交或拒绝后清理。

数据库已完成的回执不能被迟到的无回执缓存覆盖；正常人工验收、冻结合同和正式下载保留相同回执。拒绝写回后按数据库事实恢复仍对应被拒快照的任务缓存，不覆盖并行新缓存。完成通知也必须与持久化后当前任务一致。

任务创建入口剥离客户端提供的回执、远端任务 ID、适配器、状态、幂等键、轮询及重试时间等服务端字段。单建、计费创建和批量创建共享此入口，业务 metadata 保留。运维 `db:import-json` 仍属于可信备份迁移边界，不是公开用户导入接口；本步不把任意外部 JSON 当作可信 Provider 来源。

## 交付核验

新增稳定要求 ID `provider-completed`。有效完成回执可满足该要求及兼容 ID `provider-accepted`；只有远端接受记录时仍为 `observed`。结构错误、身份/attempt/媒体版本不一致的回执不能通过。

交付只读查询和正式下载还会重读当前对象，主媒体完整字节核验通过才返回 Provider `passed`；对象被同长覆盖时失败，存储不可用时待补。正式下载的事实指纹包含回执，捕获文件至授权落库期间即使时间戳不变，回执增删改也会拒绝授权。

本步保持已有冻结合同和页面默认草稿。**只有合同明确包含 Provider 要求时才强制要求此回执**；无该要求的旧合同仍遵循既有任务、媒体、内容、物理及连续性门禁。不能描述为所有历史下载已强制 Provider 完成证明。
