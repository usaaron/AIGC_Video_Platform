# 视频自动接回与人物参考图修复

本轮基于维护版及 `b8d0aeb` 视频进度修复，继续解决查询失败后需要人工找回，以及人物参考图可能在后台丢失的问题。独立剧本模块保持维护版。

## 行为

- Dora 已提交任务查询失败时按 5–60 秒退避，保留原远端编号，不再次提交或扣费。
- 达到正常等待上限后结束本地任务并退款，后台每分钟认领最多两条可恢复任务，继续只读核对，最长 24 小时。普通版权拒绝、用户取消或归档不进入自动找回。
- 对账服务直接查询 Postgres，不依赖活动任务缓存。独立租约在进程重启后可续查。退款标记和实际账本都通过校验后，视频、尾帧、任务、镜头关联和审计一起完成；旧缓存不能覆盖新结果。
- 用户已改镜头、选择新视频或提交新任务时，晚到成品只进入历史，不改变当前选择，也不被完整成片的自动回退选择。
- 明确上游失败立即退回积分；周期补退将标记和更新时间持久化，重启不重复退款。失败分类使用稳定代码，并仅保留格式受限的上游请求编号用于诊断。
- 界面区分“生成中”“核对中”“上游拒绝”，无真实进度时显示等待时长，不显示固定估算百分比。实际退款标记存在时显示退款状态。

## 人物与场景引用

原后台只保留连续视频依赖，遗漏 `metadata.images` 中已完成的生成图任务。自动参考图读取失败还会被忽略，可能导致用户选了人物，实际请求却没有人物图。

创建任务时现在保存可读取的原图地址，活动任务依赖闭包保留同租户、同项目的图像来源；选定资产的图像无法读取时明确失败，不静默丢弃。Dora 保留已确认面部，并额外传递已确认的全身造型；全身图不再被别名替换成脸图。手动编号图与连续镜头尾帧顺序保持稳定。提交成功时与远端任务编号一并写回 `providerReferenceImageCount`，不记录签名 URL。

AI 虚拟人物的 AIGC 入库状态不等于真人授权，也不是视频上游版权审核的豁免。资产界面按实际类型显示“AI人物已入库”，说明视频通道会独立审核；仅确认面部而未确认全身时提示服装和体型可能变化。不会将虚拟人物要求为真人授权，也不会自动重复提交被拒绝的内容。

## 验证与发布边界

使用独立临时 PostgreSQL/Redis 验证退款持久化、重启、并发认领、审计回滚、租户隔离、旧缓存写回与晚到结果选择，不连接生产数据库运行测试。Provider 使用替身；本轮没有创建付费视频。

专项覆盖真实 18 积分扣退、超时后重新启动 Worker、独立后台接回、尾帧与镜头关联及审计一次性，整条演练没有调用 Provider 提交接口。Web 288 项通过，浏览器桌面/手机流程 37 项完成验证（入库文案断言单独更新后通过）；所有应用构建、lint、格式、架构及部署安全检查通过。完整 API 首轮发现的提交异步调度回归已修复，原有 44 项队列测试保持原断言通过。

最终 API 在专用 PostgreSQL/Redis、内部测试网络中串行完成：94 个文件、711 项通过、2 项默认跳过，退出码 0，无未捕获异常。两项跳过是需私人小说全文及显式开关的既有样本回归。复核时发现 `pg-pool.end()` 早于底层连接完全退出，测试 fixture 立即强制删库导致 57P01；fixture 改为最多等 5 秒让目标库连接自然退出，再普通删库。实际连接泄漏仍会明确报错并保留测试库，未吞掉异常。

2026-09-21 正式上线的应用提交为 `a0e1e7e029c05e3a9de1f8ec0962b5ab9431fb0f`。上述 fixture 修正仅用于测试，生产构建明确排除 `src/testing`。发布后 readiness、登录及管理员边界通过；三条用户新视频均已自动完成、完整解码通过、Range 206、尾帧可读并关联正确镜头。历史版权失败保留原失败状态和 18 积分退款，通过受审计脚本补齐稳定错误分类。没有额外提交付费视频；本轮技术验收不代表已完成生成画面与人物原图的视觉一致性验收。

发布只切换主项目 Web/API/Worker，发布前检查 Host 与 Script 活跃任务、对账任务、队列和请求，保存源码、配置、数据库备份。Script/数据库/Redis 不重建，健康失败恢复原应用镜像，不自动恢复数据库。

上游明确版权拒绝仍会失败并退款；自动找回只处理网络/状态查询/等待超时导致的本地跟踪中断，不能把上游实际未生成的内容变成成品。24 小时核对窗口到期后停止自动查询。
