# 状态证据对应、动作归属与描述失效：本轮修复和实测

2026-10-11。本轮为通用分镜生成及保存规则优化，已在本地启用；阅读样本的两项指定问题改善，不能宣称四例全部通过内容验收。

## 修改范围

主项目仍为 `main-deployed` / `codex/script-host-ux-20260920`；实现位于独立仓库 `script-master-update` / `codex/script-master-update-20260920`。保留原有未提交修改，未提交整仓、未发布线上。

1. 新分镜执行合同 v3：每条变化证据增加 `target_key` 与 `effect`，必须对应所属状态及该次结果。沿用正文逐字引用、时间区间、动作/观测/未知分类检查。提示词要求核对对象、维度及真正导致变化的过程，不以同段另一动作或结果描述冒充依据。
2. 每条镜头动作增加对应的 `action_evidence`。动作与依据等长同序；完成事件须属于本镜正文引用，跨镜重复使用同一事件依据会被拦截；持续状态不可引用未来正文。提示词区分“读着/读完”“握住/拿起”等持续与完成行为，要求场间承接不重演。
3. 状态增加 `valid_while`。依赖条件失效时从派生状态中退出，依赖恢复也不会自动复活旧描述；须有新正文记录。检查未知依赖键、未知值、自依赖及循环依赖。已有显式错误快照仍报错，不静默覆盖。旧版 v0–v2 保持读取兼容，保存不能降低已有校验版本。
4. 前端保持旧稿字段可选，拆合镜携带对应证据；v3 合镜不再把承接说明额外插入为一条无依据事件。OpenAPI 与生成类型已同步。
5. 真实复杂返回多了 `design.execution_plan_ref: "design.execution_plan"`。增加窄范围兼容：只有这个精确自引用且目标确为现存对象时才去除冗余标记；其他值、内容型字段或缺失目标仍严格拒绝。原始响应留存，不改动作或状态内容。

核心代码：`backend/app/modules/preproduction/{binding_guard,transition_guard,execution_guard,generation_schema,models,proposal_wire,service}.py`；前端 `frontend/lib/storyboard.ts`。

## 同四份正文的真实验证

来源仍为 `work/scene-small-eval-20261011/{gate,door,handoff,quiet}/source.json`，四份 SHA256 与前轮相同，没有为测试手工修正文或输出。

模型 `deepseek-v4-1-flash-260910`，high thinking；共 **4 次真实请求**，每例 1 次调用、1 次传输。生成时冻结同一版提示词和代码。前三份直接成功，复杂样本完整返回后因上面的额外字段被严格解析拒绝。修复格式兼容后，把四份原始返回值通过最终公共 Service 在独立数据库回放，**新增模型调用 0 次**。因此不能将回放说成又一次成功的真实生成，也不能宣称最终代码的首轮请求完成率为 100%。

复杂样本不能靠“全场被拦”推断新规则识别了全部内容问题：全场受限主要还包括模型把 51 秒场景参考预算标成执行冲突。该输入的整集剩余预算实际为 105 秒，51 不是整集剩余额度；这一判断也需后续纠正。独立动作依据错误涉及第 2、4、5、6、7、8、9 镜，其中多项实际是台词表演重复写入动作字段，不能宣称这些台词不属于正文。

前轮的“终端显示读数被当作转向过程”“栏身倾斜被当作人物肩部接触”在本次未以同样状态条目再次出现：模型减少了部分状态维度，不能据此宣称这两类语义错误已被自动可靠识别。`target_key/effect` 一致性检查也不能证明模型自填的对应关系在语义上正确。

## 剩余边界

这轮解决了可机械确认的对应错误和条件失效传播，并使阅读例的已知问题消失。自由文本是否真正对应动作、hold 是否夹带新动作、模型是否漏列关键状态，仍依赖语义判断。下一步应先针对这些残余误判做独立的语义验证设计，并澄清场景参考预算与整集上限，避免继续堆字段或用关键词误拦合理表演。本轮不据此启动整集视频或扩大自动生成范围。
