# 人物身份约束与确认后自动加白

## 行为

- 人物图片的服务端质量规则升级为 `quality-floor-v3`，最终正向提示词明确人类身份。高级完整覆盖保留自定义描述，但不能移除这条身份约束。明确选择动物的角色仍可生成动物；场景、物品和服装不套用人物身份。
- TokenAdvent JSON/multipart 请求原先用“避免出现”包裹包含“不要”和“保持”的完整规则，存在双重否定和正向要求反转。现改为按原意执行的画面约束。
- 用户确认平台生成的人类面部后，服务端保存面部并自动提交后台 AI 人像加白任务；任务默认消耗 1 积分。候选图不会逐张自动注册。
- 动物、直接导入、已授权真人不自动走 AI 入库。导入 AI 图片仍可手动注册。真人 H5 的能力限制保持原状。
- 重复确认同一面部复用任务与有效资源，不重置已确认的全身；换脸会清理旧绑定，旧任务不能把旧面部写回。
- 面部确认与自动任务创建分别返回结果。配置不完整、积分不足或任务失败会显示原因，已保存面部保留；失败不会因普通保存而自动循环扣费。
- 修复精简轮询省略 `outputs` 时被前端补成空数组的问题，防止面部候选图在轮询后消失、确认按钮禁用。确认期间锁定编辑，避免迟到响应覆盖新选择；首次创建人物不会因 ID 改变卸载编辑器。

## 接口

`POST /api/v1/projects/:projectId/assets/:assetId/face-confirmation`

请求为 `{ faceReference: { id, url, name } }`，返回 `{ asset, registrationTask, registrationError }`。接口校验账号权限、项目归属、图片来源与生成完成状态，任务使用现有积分事务、Outbox 和 Worker。客户端不直接调用素材供应商。

事务、恢复和遗留接口边界见 [面部确认接口说明](FACE_CONFIRMATION.md)。

## 验证与限制

此次使用 Provider 测试替身验证实际请求内容和自动入库状态流转，不能据此保证模型每次都不会生成动物；没有新增出图后的物种识别审核。已生成的错误候选需要重新生成。

- API 隔离 Postgres 与业务回归：8 个文件、79 项通过，包含 16 项面部确认集成测试；确认/手动创建并发幂等、服务端价格、Outbox、失败退款、余额不足、来源隔离及旧绑定回写均覆盖。
- 图片提示词和 Provider 请求测试、API build/lint 已通过；前端资产与工作区专项 13 个文件、97 项通过。
- 新增界面 E2E 5 项通过，覆盖首次创建后的确认、确认期间锁定操作、失败恢复以及迟到的人像同步；contracts 相关 11 项通过。
- 本地界面使用替身 Provider 验证：确认后自动进入后台任务并同步 Active；积分减少 1，重复确认积分不变，动物确认不入库、不扣费。桌面与 390×844 iframe 视口检查通过。
- `pnpm check` 格式通过，停在既有 `apps/api/src/app.test.ts` 的 5270 > 5267 行门禁；没有抬高门禁，不能称全仓完整检查通过。相关 Repository、Worker 文件通过拆分减行并收紧基线。
- 此次测试库初轮经 SSH 隧道初始化超时后留下 schema，旧 migration 的跨 schema 约束名查询导致再次初始化失败。仅重建本次隔离测试容器后，在服务器内顺序运行通过；未修改已提交 migration 或生产数据库来迁就测试。
