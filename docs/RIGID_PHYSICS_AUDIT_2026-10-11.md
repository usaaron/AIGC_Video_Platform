# 刚性物体物理合同与逐帧验收

2026-10-11 按当前 1-1 失败样本补齐第一版物理约束层。范围只覆盖刚性物体和镜头连续性，不触发整集生成，也不改正式剧本或已有视频。

同一批问题已回写到生成前工作流：提示词预检升级为 `video-preflight-v3`，单一连续镜头中若正向要求镜内硬切、跳切或转场会在扣费/派发前阻断；固定底座同时写栏片弯曲时也会阻断，要求作者明确整体刚体运动，或补充可验收的柔性/铰接变形模式。提示词编译器升为 `seedance-storyboard-v22`，对连续镜头追加单一时间流约束，并要求栏杆左右底脚、闸门轨道连接点持续可见。1-1 样片没有修改，也没有重新生成。

## 已实现

- `packages/prompting/src/rigidPhysicsContract.ts` 定义 `rigid-physics-v1`：固定隔离栏、滑动闸门、锚点、允许位移、接触区和镜头模式。
- 轻量预演只允许合同声明的整体运动。固定栏杆收到位移、弯曲或伸缩请求会失败；滑动闸门发生轨道横向位移会失败。
- `GenerationService` 在视频任务快照中保存 `rigidPhysicsContract` 和 `rigidPhysicsAudit: pending-evidence`，后续验收不能把“生成完成”当成物理通过。
- `apps/api/src/core/generation/rigidFrameAudit.ts` 使用 FFmpeg 缩略灰度帧检测硬切，并消费逐帧锚点、跨度、杆距和人群质心证据。缺少可追踪锚点时返回 `needs-evidence`，不自动判通过。
- `apps/api/src/scripts/auditRigidVideo.ts` 可对本地 MP4 离线生成 JSON 报告。
- 生成队列轮询和分镜验收面板已展示物理状态、阻塞原因、底脚/连接点覆盖；物理验收未通过时，内容“验收通过”按钮和服务端写入均被阻断。历史任务没有合同的情况会从源提示词补建合同，并保留审计版本历史。

## 当前边界

这版是“物理合同 + 轻量预演 + 严格验收”第一版，不是完整 3D 物理引擎，也不会直接改变 Seedance 的像素生成。要自动判断栏杆是否跟随人群移动，还需要为每个刚性物体提供可追踪的底脚/连接点或稳定视觉特征；在此之前，缺证据一律不能标记为通过。
