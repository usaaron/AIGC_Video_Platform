# 状态改变必须有过程依据：通用修复与四样本验证

2026-10-11。新规则已在本地 5183 使用的剧本后端启用。改动适用于所有新生成场景的执行状态，不按门、人物名或某个样本写关键词特判。正式项目正文、分镜与媒体没有被测试稿替换，未生成图片或视频。

## 第一步：将结果状态与变化过程分开

此前 `changes.source_quote` 只需出现在正文中，就可能把“正在通行”到“仍锁着”视为合法变化；原文确有两个状态，并不能证明中间发生了关锁动作。

现在每条变化增加：

- `basis`：`action`（明确动作或自然过程）、`observation`（仅陈述结果）、`unknown`（发生或前提未明）。
- `transition_evidence`：独立记录变化过程的 `source_ref` 和逐字 `source_quote`。

生成提示词要求逐项寻找足以解释该状态维度的过程依据：物件转手需有取得或交付过程，人物换侧需有移动或明确转场过程，开合或形态改变需有相应动作或自然过程。正文明确发生的画外动作可用，对白仅声称物理状态改变不能直接视为动作证据。不通过换状态名、重新初始化或虚构画外动作消除缺口。

生成 Schema 要求输出分类和证据列表；旧数据的保存/读取 Schema 允许字段缺省，以保持兼容。所有新生成场景使用校验版本 2，保存时取当前稿与历史稿的较高版本，不能从前端降级绕过新检查。旧稿没有被批量升级或追认为已经通过新校验。

## 第二步：执行端限制缺少过程的变化

后端确定性检查：

1. 分类是否存在；`action` 是否提供过程证据。
2. 证据是否逐字出现在引用的正文动作中，引用时间是否落在前后状态记录之间。
3. `observation` 的结果与上一值不同时，不能直接成为可信变化；同值观测不要求编造动作。
4. `unknown` 保持待确认。缺口处及其后的镜头保守限制交付，后文再次声称某个结果也不能补齐前面的缺口。

未经确认的变化保留在草稿供修订，不进入可信状态事件推演；受影响镜头不补出确定的起止状态，不编译可执行提示词。既有保存、候选采用、复制、整场导出与主站交接限制继续使用同一问题标记。

这是有条件的结构化检查：程序能核对分类、证据存在和时序，但不能独立证明任意自然语言证据与状态变化的语义对应。模型错误分类或漏列状态仍可能漏报，不能称为任意剧情矛盾的自动证明器。

## 第三步：通用反例与正常情况

新增 17 项测试，覆盖：

- 门锁、物件归属、人物位置、书本开合四种不同的“只见结果、没有过程”情况，缺口及后续镜头均被限制。
- 缺分类、缺证据、虚构引用、未来证据、过期证据、仅对白宣称和未确定变化。
- 状态保持不变无需动作、风吹开门等自然过程无需人类操作者。
- 有证据的开门/关门变化、保存再读、旧稿兼容、新稿保存不可降级。

合计 171 项相关后端、59 项前端、4 项桌面/手机浏览器检查通过，共 234 项。类型检查、OpenAPI 一致性和隔离目录生产构建通过。沿用此前相关检查范围，未声称全仓测试通过；历史自动恢复测试中与既有单次生成策略冲突的预期仍不计入这组结果。

## 第四步：原四份冻结正文的真实生成

四份正文的 SHA-256 与原样本相同，模型仍为 `deepseek-v4-1-flash-260910`、high 思考，本地单请求及场景时限均保持 600 秒。

本轮共 5 次真实文字请求：三个常规样本各一次，复杂样本首次失败后做一次完全相同输入的重试。失败记录保留，没有用成功重试覆盖首次失败。重试提示词逐字相同，代码哈希未变。

复杂样本的关键原始输出：

```json
{
  "source_ref": "action:7",
  "source_quote": "柱下那道单人核验门仍锁着",
  "after": "锁着",
  "basis": "unknown",
  "transition_evidence": []
}
```

模型同时指出需要确认是否逐人回锁、或由谁在何时锁闭，并未把其中一种猜测当成已经发生的事实。新增检查给出了“状态变化的发生或前提尚未确认”的具体问题。

为确认不是旧的冲突/时长标记碰巧拦住，另在内存副本中暂时移除这些旧标记、重新运行检查，新增因果检查仍单独拦住第 8、9、10 镜。该隔离检查零模型调用，不写回数据，也未采用副本。

原始重试稿另有全场时长待确认项，综合限制后 10 镜的执行提示词均为空；隔离库真实执行候选采用操作，被拒绝且原快照不变。三个常规样本经实际主站导入转换函数检查，交付 5 / 6 / 3 镜，无新增交接警告。所有完成请求都保留了原正文和完整、有序、无重复的引用集合。

首次复杂请求已收到正文片段，但远端流在约 300 秒中断，底层为 `RemoteProtocolError`，不是本地 600 秒时限到期。具体上游断开层尚未确认；重试成功也接近 300 秒，因此复杂请求完成性仍不能宣称稳定。

## 内容审阅的边界与剩余问题

本轮目标是验证缺少状态变化过程时的处理，不把代码检查通过等同于整份分镜可出片：

- 阅读稿首镜已写“读完眼前一页”，次镜又重复；书页位置值中的“新的一页露出”还与后来“书已合上”并存。属于动作重复、状态之间的联动和混合描述问题，未因本轮新增校验自动消失。
- 复杂稿个别 `transition_evidence` 对应不准确：终端转向的证据字段选了“屏幕上显示读数”，肩部支撑的证据字段选了栏身倾斜。相关主引用处存在动作，但专门的过程证据字段语义仍需准确绑定。
- 本轮复杂稿确实识别并拦截了先前漏报的关锁过程缺口，但仍有其他设计推断与时长问题，不能采用它推进视频。

下一步宜加强“过程证据是否真正作用于该主体和该状态维度”，并检查一个状态改变后，其他状态中的描述是否随之失效；不要再只用引用存在、格式齐全来代表内容正确。
