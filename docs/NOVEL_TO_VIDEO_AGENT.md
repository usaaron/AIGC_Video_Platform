# 小说到 AI 视频 Agent 方案

> 状态更新时间：2026-07-31

本文记录长篇小说改编成 AI 视频剧本的阶段方案。后续每完成一个阶段，先检查项目内与本方案相关的代码、交互和测试状态，再给出下一步建议。

## 目标

把 40-60 万字小说处理成可生成 AI 视频的制作资料：先稳定导入和章节边界，再逐层压缩成故事概要、改编方案、分集大纲、分场剧本、资产、分镜和成片任务。

## 阶段路线

1. 小说上传 + 自动章节切分
   - 支持 `.txt` 和 Markdown 文本。
   - 自动识别 `第一章`、`第1章`、`Chapter 1`、Markdown 标题。
   - 没有明确章节标题时，按约 6000 字自动分段。
   - 保存小说文档和章节元数据，为后续摘要任务提供稳定输入。

2. 章节摘要 + 全书故事概要
   - 按章节逐步生成摘要，避免一次性请求超长文本。
   - 汇总人物、世界观、时间线、地点、关键物件和伏笔。
   - 建立可人工修订的故事概要，作为后续改编的事实源。

3. 多套改编方案
   - 基于故事概要生成 3-5 个改编方向。
   - 每个方向包含题材定位、主线取舍、角色弧光、集数建议、风险提示。
   - 用户选定一版后再进入剧情结构。

4. 分集大纲
   - 按短剧、漫剧或动画片规格拆分集数。
   - 每集保留核心事件、情绪钩子、结尾悬念和资产需求。
   - 支持单集重生，不重写全书方案。

5. 单集分场剧本
   - 复用现有剧本页的大纲、剧情结构和分场剧本能力。
   - 单集生成后自动建议角色、场景、道具、服装和音频。
   - 长剧继续按段生成，避免覆盖已确认内容。

6. 资产、分镜、生成、成片闭环
   - 镜头引用已确认资产。
   - 批量生成前做预算确认。
   - 支持单镜头重试、三视图单张重生、视频结果播放和下载。

## 当前第一步实现范围

- 新增小说导入 contracts：请求、文档、章节和导入结果。
- API 新增 `/api/v1/projects/:projectId/novels`、`/novels/:documentId`、`/novels/import`。
- 小说域已迁移到 Postgres + ObjectStorage 主路径：`novel_documents`、`novel_chapters`、`novel_boundaries`、`novel_summary_queues`、`novel_summary_queue_items`、`novel_chapter_summaries` 和 `novel_story_bibles` 保存元数据与可恢复任务状态；正文只写入对象存储，数据库保存 storage key、SHA-256、offset 和章节元数据。
- JSON Store 仅保留无数据库/无对象存储时的本地兼容回退，以及通过 `db:import-json` 执行迁移时的历史输入和备份。
- 剧本页新增“小说改编”面板，展示上传文件、作品名称、切分统计、章节预览和已导入记录。

## 当前第二步实现范围

- 新增章节摘要和故事概要 contracts：请求、结果、摘要条目、人物、地点、时间线、关键道具、伏笔和世界观规则。
- API 新增 `/summaries`、`/summaries/generate`、`/story-bible`、`/story-bible/generate`，按项目和小说文档隔离读取。
- 章节摘要按批推进，默认每批处理少量未摘要章节，避免一次性把长篇小说正文送入文本 Provider。摘要队列的 `run-batch` 已改为创建 `ai_jobs.kind = novel.summaryQueueBatch` 的后台任务；API 立即返回任务记录，Worker 调用文本 Provider 后写回队列条目。
- 全书故事概要只基于已完成的章节摘要生成；摘要未完成时返回明确错误，防止事实源不完整。
- 剧本页新增“章节摘要 / 故事概要”面板，展示摘要进度、下一批生成、故事概要生成和关键内容预览。
- 章节正文仍只在服务端内部用于摘要生成，前端和公开接口不直接返回正文内容。
- 仍待迁入 Worker 的同步文本入口：直接章节摘要 `/summaries/generate`、边界说明生成、Story Bible 生成、小说章节改编和资产建议。后续应继续沿用 `ai_jobs.kind` 区分具体操作，并复用 `ai_jobs` 的扣费、重试、暂停、恢复和失败退款。

## 验收样本策略

- 功能稳定后使用两类真实长文本做端到端验收：一部中短篇样本用于质量检查，一部长篇样本用于章节切分、分批摘要、成本控制和长任务稳定性压力测试。
- 小说导入 MVP 的单文件大小上限先以长篇样本大小为准：`5,657,407 bytes`。前端按原始文件大小限制，API JSON bodyLimit 保留包装余量，服务端按解码后正文再次兜底。
- 真实小说全文放在本地 `local-fixtures/` 或部署环境的受控测试数据目录，不提交 Git。
- 自动化测试仍保留短模拟小说，保证 `pnpm check` 不依赖大文件、外部版权文本和真实 Provider 成本。
- 真实样本验收必须显式触发，避免普通开发、CI 或页面浏览误消耗文本/视频 Provider 额度。
- 第10步已补显式样本回归入口和运行说明，详见 `docs/NOVEL_REGRESSION.md`。

## NovelSplitter v2 十步拆解

1. 规则章节识别：固定关键字、中文章回、Markdown 标题。
2. 可配置分块大小：支持自动、规则章节、固定分块。
3. 自动重叠：分块之间保留上下文，但不把重叠计入原文覆盖。
4. 切分预览：导入前展示统计、章节预览和风险提示。
5. 不丢字符校验：按源文起止位置校验覆盖，失败直接拒绝导入。
6. NovelSummaryQueue：每块独立摘要，可配置批次数量。
7. 队列控制：暂停、重试、跳过、提交进入事实库。
8. BoundaryReconciler：只处理疑似断裂边界，生成衔接说明，不改原文。
9. Story Overview：只读章节摘要、事实条目和边界说明，不直接读小说原文。
10. 样本回归：用 `边城.txt` 和 `倾覆之塔.txt` 显式验收上传、切分、边界和队列稳定性。

## 下一步提醒规则

每完成一个阶段后必须检查：

- contracts 是否覆盖请求、响应和边界条件。
- API 是否有权限、租户隔离、错误路径和测试。
- 前端是否有明确入口、失败提示、移动端布局和不会误触发付费任务。
- 文档是否同步当前真实状态和限制。

第二步完成后的建议下一步：多套改编方案。基于故事概要生成 3-5 个可选择的改编方向，用户选定一版后再进入剧情结构和分场剧本。
