# 视频内容验收与生成前检查

承接首镜持物错误及倒计时跳数修复。当前 5183 本地已启用；未部署线上，本轮未调用付费模型。

## 生成前：限定规则检查

`inspectVideoPreflight` 只检查已知导演分镜格式中“局部锁定／屏幕呈现”的明确文字要求：同一命名人物同一只手被全程锁定持终端和持枪、同时要求显示并禁止显示数字。明确冲突在 API 扣费前以 409 返回并提示修改。Worker 在提交模型前再核对一次，覆盖历史排队任务。

可读数字要求只作风险提示，不擅自删除剧情；资产说明中的姿势、特写用途继续由 v19 编译器按外观参考处理，并记录相关预检提示。不同人物持不同物品、动作先后变化、对白和全场背景不按上述规则判为冲突。

这不是通用自然语言矛盾检测，也没有读取上一镜像素判断人物位置。未命中规则不代表剧本或画面已经验收。

## 生成后：版本内容验收

Provider 的 `completed` 仍表示生成技术成功，不变更任务生命周期或伪造失败退款。Seedance 视频在没有有效验收记录时一律视为“待内容验收”，历史视频也不自动通过。分镜页当前选定视频下提供：

- 已观看，验收通过：允许这个版本供已排队的连续镜头承接。
- 标记画面问题：必须填写问题，后续连续镜头继续等待。
- 撤回验收：恢复待验收，不承诺停止已经提交上游的镜头。

验收记录包含操作者、时间、备注及媒体版本标识，保留变更历史。重做的新任务、存储对象替换及带摘要的本地后期输出不继承旧验收。接口核对组织、用户权限和 `expectedUpdatedAt`；并发旧页面更新返回 409。通用任务创建不能伪造验收和后期来源字段。

## 尾帧衔接

依赖调度要求前一视频技术完成、有尾帧且内容验收通过；即使客户端漏传通用依赖 ID，也按 `continuitySourceTaskId` 检查。未验收／有问题的源版本使下游保持排队，不占模型提交次数；实际读取尾帧时再次验证。独立镜头仍可并行生成。

排队扣费、取消退款沿用现有规则，并在批量确认中说明等待验收。验收通过可使已授权排队任务自动继续，不另建生成任务。验收记录只属于具体版本，不会将已排队任务的源版本偷偷换成重做版本；源版本被标记问题且需要重做时，应取消仍依赖旧版本的待执行任务，再按新选定版本重新提交。
