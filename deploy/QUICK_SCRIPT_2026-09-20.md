# 主项目快速剧本（本地候选）

主项目中的中文剧本新增独立 `creationMode: quick`。新的主项目创作默认使用快速流程；没有模式标记的旧项目保持原流程，没有正文的大陆项目可主动选择「快速创作」。独立剧本大师及海外标准流程继续使用既有工作台。

## 用户路径

故事想法 → 故事梗概（确认一次）→ 人物与每集故事安排（确认一次）→ 顺序生成、保存、检查整部正文 → 编辑 → 明确交付到主项目资产设计。篇幅默认 8 集、约 8,000 有效正文字；首版限中文、不超过 10,000 有效正文字、最多 6 个核心人物、1 条主线和至多 1 条支线。

快速页不要求长总纲、递归故事树或逐集批准。人物、固定事实、故事走向和逐集逐场安排由同一次计划生成产生，仍必须满足可执行合同。正文沿用结构化 `DraftMasterScript`，检查保留现有短剧的对白、动作、时长、语言及可拍性要求。

主项目通过既有 `script_master_delivery.v2` 交付已保存正文与有来源哈希的资产依据，之后仍走主站资产 → 分镜；快速页没有另加独立分镜阶段。

人物、固定设定和各集安排默认显示简短摘要，展开后可直接编辑。阶段切换与交付前检查未保存修改；服务器版本变化时保留本机编辑备份，提供可读的恢复内容。界面沿用主项目暗色主题，在手机宽度下变为单列。

## 保存、恢复与质量边界

- 新增 `/story-projects/{project_id}/quick-script` 及 `/actions`，沿用宿主鉴权、项目权限及账号隔离。状态位于既有 workspace 的 `quickWorkflow`，不需要数据库迁移。
- 每次动作携带操作 ID 和快速状态版本，模型请求前先原子占用，响应后合并最新工作区的其他字段；普通工作区自动保存不能覆盖快速状态、设置和正文。
- 一次 `advance` 只运行一个阶段。完整正文先持久化，再检查；检查失败恢复时使用同一份正文。页面驱动后续阶段，关闭或离开页面后不会继续自动生成整部作品，重开需明确继续。
- 每集一次合并语义检查，加本地机械检查；至多一次局部修复及复核。关键未解决问题或重要歧义阻断后续依赖，不把草稿标成通过，不自动运行多轮风格深化。
- 保存作者修改后，后续事实和检查失效，已有后续正文保留。首稿及历次被替换的正文版本保留在快速状态内。
- 完整前文按保存顺序进入上下文；不为适配窗口删段。默认 65,536 tokens 是应用的保守操作上限，并与适配器上限取小值，不代表渠道能力已实测。可用 `QUICK_SCRIPT_CONTEXT_TOKENS` 调整，实际容量应按对应渠道核验。
- 转标准流程保留梗概、人物、正文及短篇目标，只补标准流程所需规划；不伪造总纲或故事树批准，不从首集重新生成。

## 验证与发布边界

本轮使用测试替身与隔离 SQLite 验证，不调用付费模型。无修复 `2N+3` 次调用是被测试的流程预算，不代表真实模型质量或速度达标。方案要求的 3 种故事各 2 次、5千/8千/1万字及相对标准版耗时对比，仍需实际模型验收；海外双语快速流程暂未开放。

跨仓库验收使用浏览器实际交付的两集测试稿，经主站真实 Fastify 导入接口及隔离 AppStore 运行资产建议。由此修复 `INT. 档案室 - 夜` 被截为 `INT` 的场景名问题；资产解析器版本更新为 v3，补充内景、外景及混合场景标记回归。该测试验证正文、幂等及人物/场景建议，不代表真实图片或分镜生成已验收。

仅本地改动，未推送、未部署。主站 5181 仍是示例 API，不能将本地 UI 交接验收等同于生产 PostgreSQL、资产生成和分镜制作完整验收。

## 同日衔接审查修复

- 新项目在快速版支持的 75–115 秒内继承主站单集时长；不兼容的主站时长使用标准流程。旧项目进入快速版时保留上传资料与已有梗概，仅有梗概也能继续。已有正文或已经明确转标准的项目不再提供不可用的快速入口。
- 干净的浏览器缓存不覆盖新的服务端资料；断流后读取保存结果，活跃操作只读等待，租约过期后由用户明确恢复，不自动重放请求。
- 全局检查问题、重大歧义和不存在的场次不误入局部修复。正文允许增删动作、台词和场景，数量问题可以手动修复；后续集阻断时聚焦问题剧集并显示具体问题。未知修复结果保留已预约次数，避免再次发送付费请求。
- 作者修改及自动修复的场次通过 `llm_metadata.quick_asset_evidence_invalidated_scenes` 标记旧资产清单失效。交付不把旧清单重新绑定到新正文哈希，主站从当前正文重新分析；文本导出也不再附带陈旧的生成索引。
- 主站资产页直接复用快速提取与建议确认，正文交付后可接着加入人物、场景和物品；不自动生成图片。部分资产写入失败时刷新已成功项并允许重试。
- 主站长场次拆分保留完整动作、对白与表演顺序，不丢较长字段，不将对白重复复制成动作；实际分镜生成、资产去重和参考匹配已通过隔离真实业务代码验收。
- 修订稿省略过期的「本集信息」后，主站仍识别正式场景与对白结构；资产解析器更新为v4，回退恢复明确人物/场景且不覆盖完整空依据。仅在动作叙述出现的无台词人物和道具仍可能需在资产页补充。包括浏览器实际修订交付在内的10项跨仓业务测试通过。

首次审查保留了已有分镜后的覆盖保护与核对入口；原先缺失的制作修订流程已由下面的同日补充实现。首次验收记录保留在工作区 `work/quick-script-handoff-review.md`。

## 同日补充：返修交付与恢复体验

已有分镜后再次交付修改正文，默认同步仍返回保护提示；用户可在原弹窗选择「保存修订并更新分镜」。前端仅为纯正文交付发送 `storyboardRevision: preserve-history`，并将该选择纳入幂等标识。成功后等待主站刷新再进入分镜页，回执说明保留与更新镜头数量。

主站在原项目和原剧集中保存旧正文、分镜及媒体关联，可靠匹配的镜头继续复用；修改场次或不能可靠匹配的镜头重新拆分，不调用付费模型。旧版本在主站「制作修订历史」中查看，不自动清理历史媒体，暂不支持整版一键恢复。镜头任务创建与返修同步加锁并复查，避免失效镜头继续入队扣费。

快速页显示已保存集数、已检查集数、最后保存时间和当前步骤。断流后立即只读查询，后续轮询不自动重放模型请求；读取请求15秒超时后可重试，不改变模型调用超时。找回新版本时保留未保存编辑的可读备份。保护期间显示剩余等待时间及「刷新保存进度」；超期后「恢复中断步骤」只恢复状态，由用户明确继续。确实无法确认结果时最长20分钟保护仍保留，关闭页面仍不会后台续写。
