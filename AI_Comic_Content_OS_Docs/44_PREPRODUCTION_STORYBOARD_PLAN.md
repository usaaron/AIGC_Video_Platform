## 1. 对话承接与范围

来源对话：[查看 Liblib 页面内容](thread://01a07bda-31ee-75a0-aed3-df34960fc0db?hostId=local)。该对话先要求研究作品，再讨论如何融入现有流程，明确“先不操作只是讨论方案”，随后把本团队范围收敛到正式图片、视频生成之前。本次将最终方案与中断问题落入项目文档。

中断问题是“生成图片和视频的相关描述是我这边出？”答复：**由本团队的系统产出。系统根据已确认剧本、视觉方案、资产设计和分镜自动生成图片提示词与视频提示词，创作者负责选择、修改和确认。实际图片、语音、视频生成与剪辑由下游团队完成。**

| 责任方 | 负责内容 |
| --- | --- |
| 创作者 | 提供故事方向与偏好；阅读、修改、锁定和确认关键内容；选择交付版本 |
| 本系统 | 正式剧本、视觉方案、场景与镜头设计、文字资产规范、图片与视频提示词、连续性与依赖关系、交付检查、版本化前期包 |
| 下游系统／团队 | 选择和配置实际生成模型、绑定参考图片或音频、执行生成、选片、重试、配音、剪辑及成片管理；回传需要调整的创作描述 |

最初讨论中的 `Generation Tasks`、视频生成入口和生成结果管理已被上述分工取代。声音在本系统中是角色声线、表演、对白及音效的文字要求，不包含语音合成。生成提示词是交付内容，不代表已提交生成任务。

当前长篇创作主流程与正文质量优先级继续作为基础。规模和市场配置引用 Current Status，不把历史 60 万字容量研究当作当前产品承诺。分镜、资产描述和提示词不计入剧本正文字数。

## 2. 从参考作品吸收什么

研究依据为 [《弥寿计划》Ⅲ画布整体阅读笔记](../libtv-mishou-iii-notes.md)。本文使用已有阅读记录，不宣称重新核验了页面、全片声画或模型执行效果。

| 已记录的制作方法／问题 | 项目中的设计要求 |
| --- | --- |
| 全局美学、场景规则、逐镜执行文本相互配合 | 用“项目视觉方案 → 场景设计 → 镜头执行”分层组织文本 |
| 人物、地点、武器与特殊形态跨段复用 | 稳定资产身份、版本化设计、服装／伤势／形态变体与使用关系 |
| 镜头明确动作顺序、对白、摄影、声音和限制 | 以结构化分镜编译提示词，支持定位到正式正文来源 |
| 素材连线与局部 Mixed 编号共同提供参考 | 内部保存稳定引用，由交付适配层生成目标占位符与绑定清单 |
| 镜号、引用文本、外观与数量存在版本差异 | 检查引用与依赖版本；改稿只产生有范围的候选，不静默覆盖 |
| 总纲、分段文字、生成输出和最终剪辑并不相同 | 区分叙事事实、制作建议与实际输出；提示词不能充当已生成证据 |

借鉴的是细节组织和生产准备方法。作品的剧情、专有角色、美术风格、21:9、30 秒、模型名称、禁用 BGM／字幕等不成为所有项目的默认要求；原始作品文本也不自动进入运行知识库或 Prompt Library。

## 3. 产品流程与低操作界面

```text
创意输入 → 故事圣经 → 递归剧情树 → 分集计划 → 正式剧本
                                                    ↓
                          分镜：视觉方案、资产设计、场景与镜头编排
                                                    ↓
                          图片／视频提示词 → 交付检查 → 前期制作包
                                                    ↓
                                      下游图片／语音／视频生成及剪辑
```

已有一集正文即可开始编排候选，无需等待整部长篇。用户在正文之后主动点击“编排本集分镜”；进入页面或确认上游规划不会隐式启动。首次编排自动准备所需视觉和资产设计候选，按场保存进度，显示可读结果与待确认项；失败、暂停或恢复从已保存步骤继续。

左侧只增加正文之后的同级“分镜”栏：**故事圣经 → 剧情规划 → 正文 → 分镜**。分镜内按“集 → 场”导航，中央按剧情顺序显示镜头列表；视觉方案、本集资产、提示词和交付内容在该页内按需展开，不增加无限画布、节点坐标或连线操作。

每镜默认显示镜号、预计时长、画面动作、对白和简短镜头说明。摄影参数、来源、资产、连续性和完整提示词放在展开详情。用户可直接编辑，也可沿用局部自然语言修改，例如“这里拆成两镜”“暂不露脸”“保留台词，增加停顿”。

需要覆盖的操作与状态：

- 本镜、本场、本集或指定后续范围的修改；拆分、合并、排序和撤销；镜头 ID 不因显示序号改变。
- 锁定外观、对白、镜头或时长；比较候选与当前版本，再选择采用。
- 聚合影响说明，例如“修改该服装涉及本集 5 镜”；受影响项与未决项可直接定位。
- 无正文、生成中、部分完成、失败可重试、待确认、来源已变化和已交付状态；已有结果在恢复时仍可阅读。
- 桌面和移动端均可完成同一核心流程；详情逐层展开，长对白与提示词正常换行。

核心操作保持为“读正文 → 编排分镜 → 调整关注部分 → 导出交付包”。依赖关系由结构化数据和程序维护，模型负责有边界的创作任务；不要求模型在聊天记忆中保管整张依赖图。

## 4. 剧本改进与来源边界

继续遵守 [合作方剧本格式合同](../PARTNER_SCREENPLAY_FORMAT.md) 和 [内容完整型剧本模板](43_CONTENT_COMPLETE_SCREENPLAY_TEMPLATE.md)：信息页与场景清单独立，正式正文保持动作、表演提示和对白的真实交错顺序，不混入分镜参数或生成提示词。

已有 `content_manifest`、场景因果字段和正文可以提供地点、人物、目标、阻力、结果、必要道具与进出状态。改进优先进入已有版本化生成提示和上下文，使动作明确到“谁在何处做了什么、他人如何反应、局面如何改变”；补足入口出口、相对位置、道具归属、伤势体力、人数和人物认知变化。细节服务因果、选择、信息揭示和情绪，不为增加字数机械填摄影术语。

“关键视觉事件、必须保留动作／对白、观众此时可知信息、空间和状态要求”由独立前期步骤从正文提取为候选。摄影设计不能新增已发生的剧情事实；发现正文缺口时，提出正文修订候选，用户采用新版正文后再更新对应分镜。

来源规则：

- 每次编排绑定所选正文的不可变快照、内容校验值和来源信息。仅存在本地草稿时可形成标明来源的分镜草案；正式交付要求明确选定、确认并冻结的正式剧本版本。
- 总纲和已确认规划约束人物及世界，但不能把尚未写入本集正文的未来事件直接拍出来。相关来源冲突时保留冲突，交由修订处理。
- 缺省或兼容回填的场景清单属于提取线索，空道具数组不证明没有道具；应结合本场完整正文核实。
- 发型、材质、服装细节等未被正文规定的内容标为设计建议，记录来源与确认状态；不能伪装成作者已经确定的设定。

## 5. 三层分镜与三种粒度

| 层级 | 主要内容 |
| --- | --- |
| 项目视觉方案 `VisualBible` | 风格、色彩、光线、材质、画幅、表演和声音基调、禁止元素及适用范围 |
| 场景设计 `SceneDesign` | 叙事目的、信息揭示顺序、人物与空间布局、行动节拍、时长预算、进出状态和转场 |
| 分镜计划 `StoryboardPlan` 内的镜头 | 稳定 ID、显示镜号、正文来源、剧情作用、预计时长、景别／构图／机位／运镜、动作顺序、对白／声音、资产引用、起止状态与锁定项 |

焦段、慢动作、一镜到底和特殊摄影参数按叙事需要提供，不要求每镜全部填写。声音区分对白、表演、环境音、音效和音乐；无 BGM 与保留对白、音效可以同时成立。

**故事场景、摄影镜头和建议生成片段是不同对象。** 一个场景可以包含多镜，下游一次生成也可能覆盖多镜。前期包可以给出 `GenerationBrief` 分组建议与镜头映射；片段上限、是否支持首尾帧／音频参考等来自已约定的下游能力配置，未知时标为待适配，不固定假设 30 秒或任意厂商能力。

时长按顺序、重叠和停顿估算。对白和动作可同时发生；不能把所有动作时长、对白时长简单相加，也不能只取两者最大值而忽略必须先后发生的动作。超预算时优先提出拆镜、重排或正文修订候选，不能静默删台词、关键动作或剧情结果。

## 6. 资产设计与提示词职责

`AssetBible` 聚合项目内的文字资产设计 `ProductionAssetDesign`。角色、地点、道具、群像、载具、特殊形态等使用稳定身份；服装、伤势、损坏和变身通过变体引用关联，避免同一人物被多次创建成互不相识的资产。

资产记录包含：ID、类型、名称、故事用途、正文／人物来源、固定特征、状态变体、视图要求、表情或动作范围、禁止变化项、相关镜头、版本与确认状态。首次出现补齐设计，后续按适用范围复用。

图片尚未生成不阻止前期包交付：引用使用稳定设计 ID，绑定状态明确为待下游生成／绑定。人物正面、侧面、背面、面部近景或道具独立视图按实际需要提出，不机械要求所有资产都有三视图。创作者可以提供已有参考；下游绑定真实素材时记录其对应的设计版本。

| 交付文本 | 由系统组合的内容 | 下游负责 |
| --- | --- | --- |
| 图片提示词 `ImagePromptSpec` | 视觉规则 + 资产固定特征 + 本次状态／视图 + 构图／背景 + 禁止变化项 + 参考要求 | 选择模型、绑定参考图、设置执行参数并生成图片 |
| 视频提示词 `VideoPromptSpec` | 场景规则 + 按时间发生的动作／表演 + 摄影设计 + 原文对白／声音 + 资产版本引用 + 连续性输入输出 + 限制 | 绑定图片／音频／首尾帧、按能力转换参数、生成与选片 |

系统内部的规划提示来自现有 Prompt Library／Strategy／Builder 机制；输出给下游的 `PromptPack` 是独立、可审阅的制作产物。语义内容从已选版本编译，特定模型的语法、占位符与能力限制通过版本化 Handoff Adapter 转换。通用描述和厂商指令分开保存，不能把用户手改完整 Prompt 当作绕过所有资产锁定与正文约束的入口。

用户可改结构化字段、追加镜头指令或修改提示词候选。手改项保留来源和覆盖范围；重新编译时展示差异，保护锁定项。若手改提示词与正文或资产冲突，应显示冲突并形成候选，而非默默恢复或覆盖。

### 原创说明例

以下仅说明文字分工，不是运行 Schema、真实生成结果或参考作品内容。

```text
正文：林岚左手握着钥匙，右手拉住将要关闭的门。
      她回头，对门外的同伴说：“先进去。”

图片描述：角色 design.linlan，正面全身参考；深灰短发、蓝色工作服，
          服装与已确认设计 v2 一致，左手持黄铜钥匙；纯净背景，
          不新增徽章，不改变发型和服装配色。
          （外观来自已确认设计，不由这句正文单独推断。）

视频描述：使用角色占位符 {{asset:design.linlan@v2}}，门与走廊引用本场设计。
          林岚保持左手握钥匙，右手撑住向内关闭的门，回头看门外同伴，
          说“先进去”；说话期间保持撑门动作。摄影机在门内侧中景轻推，
          门铰链声与对白保留。结束时门仍被撑住，钥匙仍在她左手。
          不交换持钥匙的手，不提前让门关闭，不添加未写出的后续情节。
```

占位符语法只是通用设计示意，正式格式与下游联调时确定。用户不必逐镜写上述两类描述。

## 7. 数据、版本与变更影响

以下为拟议对象，不是已发布 API 或数据库 Schema：

| 对象 | 职责及关键依赖 |
| --- | --- |
| `PreproductionSession` | 独立保存编排范围、步骤、状态、重试和确认记录；绑定源剧本快照 |
| `VisualBible` / `SceneDesign` | 项目及场景的制作表达规则，分别版本化 |
| `StoryboardPlan` / `Shot` | 场景镜头、稳定身份、正文覆盖、排序、局部候选及锁定 |
| `ProductionAssetDesign` / `AssetBible` | 项目资产身份与设计版本、变体、参考及使用关系 |
| `PromptPack` | 分别保存图片／视频提示词、编译来源、覆盖指令与适配版本 |
| `ProductionContinuitySnapshot` | 本次交付需要的状态切片、叙事来源和制作约束，不另建叙事正史 |
| `GenerationBrief` | 片段分组建议、参考素材要求、能力假设及下游待处理事项 |
| `PreflightQC` | 结构检查与有范围语义审阅的结果、证据、未决项和处理记录 |
| `PreproductionPackage` | 冻结上述已选内容、依赖清单、确认信息与校验值 |

正文来源定位必须包括“源快照 + 场次 + `action:N`／`dialogue:N` 等段落引用”。现有 `scene_number` 和 `body_order` 数组索引均不是跨版本稳定 ID。正文插入、删除或重排后，不能只凭相同场号或数组下标沿用旧绑定；保留旧快照，重新匹配并复核不确定项。旧稿的顺序回填也不等于用户已经明确确认原文顺序。

核心依赖为：

```text
正文快照／已确认相关事实 → 场景设计 → 镜头 → 视频提示词
资产身份／设计版本 ────────────────↗
视觉方案 → 资产设计 → 图片提示词
所有选定版本、引用与检查结果 → 前期制作包
```

正文、资产或视觉规则改变时，先计算受影响集合，将相关镜头、提示词和未发布包标为待更新。只对该集合生成候选，保留未受影响内容和用户锁定项；锁定项若与新正文冲突，必须显示冲突，不能以锁定为理由隐瞒不一致。

修改默认只影响指定范围或未来内容。历史改写需要明确选择范围、比较影响并产生新版本。已经交付的包保持冻结，其“相对当前源版本已过期”状态通过单独状态记录表达，不能原地改写已交付文件。

预期流程状态为草稿、待审、已确认与来源已变化；交付产生独立不可变包。具体状态枚举在实施契约时确定。采用候选、撤销、拆并和排序均需保留可追踪来源；保存采用乐观并发控制，避免多端编辑静默覆盖。

## 8. 对接现有项目

| 当前入口 | 复用方式与限制 |
| --- | --- |
| [剧本模型](../backend/app/modules/master_script/models.py) | 读取人物、场景、清单、动作对白和顺序；场景不等于镜头，暂不向正式正文加入摄影字段 |
| [长篇与 Artifact 模型](../backend/app/modules/script_engine/long_story_models.py) | 复用版本快照和来源设计；现有 EpisodeArtifact 仅支持 draft／revised／final，分镜须独立定义持久化契约 |
| [Artifact 保存服务](../backend/app/modules/script_engine/long_story_service.py) | 叙事 Artifact 写入可能触发事件及连续性投影，禁止把分镜伪装为 final 保存；draft／final 名称本身也不能代替权威性检查 |
| [统一 Asset 模型](../backend/app/modules/asset/models.py) | 当前是可检索创作知识资产；生产设计应遵守统一身份／类型治理，增加有项目归属和版本的专用扩展，不能声称已有生产资产库 |
| [制作索引](../frontend/lib/production-index.ts)与[工作簿导出](../frontend/lib/production-workbooks.ts) | 复用索引和导出基础；名称匹配与启发式提取只生成候选，不作为已确认设计或稳定 ID |
| [正文提示构建](../backend/app/modules/script_engine/prompt_builder.py) | 通过已有机制改进具体动作、空间和状态表达；先用固定样本检验，不直接注入原作品全文 |
| [工作区阶段](../frontend/lib/workspace-stage.ts)与[左侧目录](../frontend/components/workspace-section-directory.tsx) | 设计新增“分镜”入口；前期生命周期独立于 PlanningPhase，避免被“已有正文恢复到 script”的规则覆盖 |

现有 `ContinuityLedger` 是叙事状态的派生投影，不能当作视觉资产设计的权威库。前期状态从已确认叙事来源和已选资产版本提取；摄影／服装建议不通过账本写回剧情事实。生成上下文只取本次场景、相关人物／道具及必要前后状态，历史正文和完整设计库仍被保留，不随调用范围裁剪而删除。

新领域契约进入实现时，应同步 `02_Data_Model.md`、`05_API_Design.md`、数据库迁移、前后端类型及持久化测试。本次方案归档不发布这些对象或接口。

## 9. 检查与交付

优先在生成前给足准确事实、锁定项、空间关系、信息边界和连续性要求。每次保存／编译运行快速确定性检查；模型审阅集中于阶段验收、有依据抽样或具体疑点，不默认给每镜增加多轮泛化审稿。修复必须规定目标范围、最大次数和停止条件，失败保留可读结果及未解决事项。

| 检查类型 | 内容 |
| --- | --- |
| 程序检查 | ID 唯一、引用存在、来源版本可解析、稳定排序、正文动作／对白覆盖映射、遗漏或重复引用、锁定冲突、时长预算与包清单一致性 |
| 模型／人工审阅 | 空间连贯、动作是否可执行、人物表现、信息揭示、情绪节拍、资产视觉一致性、对白与动作能否在预算内完成 |
| 交付检查 | 正式剧本已选定并冻结、必需文本与设计已确认、无失效依赖、未决项分级、待下游绑定素材与能力假设明确 |

引用和覆盖检查只能证明结构是否齐备，不能单独证明画面表达正确或模型一定执行成功。正文要求的关键动作与对白必须有映射；一段动作拆成多镜、对白跨镜或画外音需记录分配，不能把合法复用误判为重复台词。

正式交付包包含：正式剧本、视觉方案、场景与分镜执行稿、资产设计清单、图片提示词、视频提示词、引用及连续性关系、生成分组说明、检查结果、未决事项和版本清单。同时提供人可阅读文档与机器可解析 JSON；需要的文档格式复用既有导出能力。

清单必须覆盖内容及依赖：包 ID／Schema 版本、项目／集数范围、正文快照及校验值、设计／分镜／提示词版本、适配配置版本、确认记录、文件清单和校验值。现有正文 payload 校验值不覆盖所有 lineage，不能单独充当整个包的完整性校验。

缺失正文引用、未确认关键设计或失效依赖阻止正式交付；允许导出明确标识的审阅草包。尚未生成图片／音频属于正常待下游绑定状态，不应误判为前期交付失败。厂商能力未约定时可交付通用前期包，不能标为已经通过该厂商执行校验。

首次对接需确定：ID 与引用格式、版本和兼容策略、占位符绑定方式、图片／音频缺失处理、镜头与生成片段映射、可支持参数、下游反馈格式。下游模型执行失败不自动反写剧情；需要修改创作描述时回到对应设计或分镜候选。

## 10. 实施顺序与验收

实施排期见 [MVP Roadmap](17_MVP_Roadmap.md)。三期均为待开发，遵循本方案的完整目标，而不是把阶段性产物当作全部完成。

| 阶段 | 交付范围 | 进入下一阶段的证据 |
| --- | --- | --- |
| 第一期 | 改进剧本输入要求；正文快照、独立分镜状态、三层文字分镜、左侧入口、直接／局部 AI 修改、保存与恢复；视觉／资产先为明确来源的候选 | 一集正文能编排并修改、保存、恢复；动作对白可追溯；正文改动会提示来源变化；不影响原有剧情规划、正文和导出 |
| 第二期 | 项目资产设计与变体、图片／视频提示词编译、稳定引用、锁定、候选比较及依赖影响 | 同一角色跨场复用；变体与基础外观分开；改一项只影响正确范围；锁定和手改不丢失；图片与视频描述均可阅读导出 |
| 第三期 | 定向语义审阅、完整 PreflightQC、不可变交付包、JSON／文档一致性、下游格式适配与联调 | 包内引用和版本闭合；旧包可复现；下游能绑定占位符并理解待办；通用检查与特定模型执行校验明确区分 |

使用不同题材的固定样本，包括对白为主、多人空间调度、动作与道具转移、人物形态变化和延迟揭示。对照现有正文及人工准备方式，检查关键内容遗漏、人物／资产漂移、空间与状态问题、提示词冲突、人工修改量和达到可用质量的端到端耗时。不以 token 消耗或成本作为本轮优化门槛。

必需工程验证随实际改动开展：快照绑定、数组重排后的失效检测、稳定镜头 ID、局部更新与锁定冲突、并发保存、暂停恢复、不可变导出，以及桌面／移动端核心流程。真实内容质量和下游可用性需要固定样本审阅与联调证据，Schema 通过或 Mock 输出不能替代。
