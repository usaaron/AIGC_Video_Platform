# 海外连续性修复与速度复测

日期：2026-09-07。承接 [首次海外抽样](25_OVERSEAS_REAL_GENERATION_PROBE.md)。本轮使用隔离数据库；用户确认最多 6 次模型请求、全轮 900 秒，并允许只在测试进程将海外正文推理强度设为 `medium`。`.env.local` 和日常模型配置不变。

## 已完成修复

- 连续性检查原先主要比较历史检查点，现在也检查同集人物能力与物品状态中明确的单一持有人冲突。首集没有历史检查点时也能报告。
- 当前状态仍为待转运、未交接等未来描述，却标记 `transferred` 时发出警告；已完成一次交接、另有未来转运的情况不按同一矛盾处理。
- 转交物品不再等同于遗失或销毁，新持有人能够继续使用，不必先虚构重新获得的事件。
- 报告截断到 50 项前先保留阻断冲突，防止新增警告挤掉硬冲突。回归样本在修复前错误返回 `warnings`，修复后正确返回 `blocked`。
- 提示词统一集末状态：人物能力只描述可执行动作，物品持有进入物品账本；已发生的交接与未来安排分开，证据确定程度与核验程度相符。
- 海外逐句翻译明确保留动作主体、对象、受益人、否定、时态及确定程度。没有新增公共字段、自动修改正文或升级强制 Gate。

新诊断是现有报告内的警告，仅覆盖明确句式和结构化字段矛盾，不是全面语义理解。对原始失败样本执行本地复检得到 2 条警告：钥匙持有人冲突、尚未发生的工单转运；原始样本没有被修改。

修复后后端全量：`1010 passed, 1 skipped`。包含连续性正反例、两个提示词上下文路径、探针计量与重放验证。跳过项不构成真实模型验收证据。真实复测启动后增加的 50 项截断保护由独立回归验证；该次生成进程使用启动时已记录源码哈希的诊断版本，不能把后续代码改动当作已在该进程加载。

## 复测设计

- 使用与上次相同的固定 8 万字 / 48 集规划样本，抽取前三集连续生成；总纲和路线图为测试输入，不验收 AI 规划质量。
- 前集通过 `previous_episode_handoff` 和累计 `project_continuity_summary` 承接，未注入完整 `provisional_continuity_checkpoint`。本轮属于摘要续写抽样，不能宣称正式连续性账本端到端通过。完成集报告状态为 `not_applicable`，零阻断数不等于跨集检查通过。
- 海外正文使用 `gpt-5.6-sol`、Responses 流式请求、`medium` 推理，输出 token 上限仍为 32,000；修复、编辑等角色沿用配置并由物理请求计量覆盖。
- 记录实际请求参数、响应头延迟、首个非空响应体字节延迟、全请求耗时、缓存输入和供应商提供的推理输出 token。首字节可能是流式心跳，不等于第一句正文。
- 缓存输入是输入 token 的子集，推理输出是输出 token 的子集，不重复相加；未返回的用量保持未知。没有供应商价目和账单时不填金额。
- 同时修改了提示词与推理参数；与历史 `high` 样本的比较属于候选配置复测，不能分离两项变化或网关波动的因果影响。

## 第一集阅读检查

代码助手逐句阅读，不是编导盲评。钥匙状态为伊芙持有；工单以 `schedule / established` 表达尚未确认的当晚转运，旧样本两处直接字段冲突没有重现。人物能力表中的“提供旧仓库钥匙”仍可能将已发生的交接当作当前能力，新诊断只匹配明确持有句式，不能声称已覆盖所有语义变体。

- P2：`episode_001/SCREENPLAY.md:37` 后处理新增 “Don't try to push it through in the confusion.”，指责亚当趁乱投出名单，但前后文中亚当在阻止曝光，缺少动机转变的证据。数据库中保存的 `generate_pre_edit_episode_script` 检查点对应原句只有 “The list stays off the screen.”，可以定位到局部扩写阶段。
- P2：第 33–35 行 “could hurt people” 被译成“会害死人”，同时加重后果和确定程度；初稿中已有此问题，后处理未纠正。
- 自动语言字段和编辑规则检查通过，只代表这些规则未报警；现有编导诊断仍标记 `review_required`，不能据此将本集标为专业质量合格。

## 第二集阅读检查

第二集承接钥匙进入旧仓库、核对原始工单、归还原件并留下影像，最后引出诺拉拒绝科尔家族接近。前两集 60 句英文对白均具备中文姓名与译文。但仍存在：

- P2：`episode_002/SCREENPLAY.md:85` 将规划中的“停工时刻与公告所述事故时间矛盾”写成“公司的通报在之后发出”，随即断言不是文书错误。发布晚于事故本身不是所需的异常证据，核心证据含义偏移。

以上是代码助手阅读判断，不是真人编导盲评；原始正文保留不变。

## 后续重点

日常 `high` 配置继续保留，`medium` 未自动推广。速度改善不足以抵消网关空流/断流和语义问题。本轮没有超过批准的 6 次请求和 15 分钟限制。

下一轮先将探针接入产品实际的结构化临时账本投影，并记录明确的检查适用状态，再验证语义继承；同时针对网关空流/断流和局部后处理引入的因果偏移做独立诊断。完成这些后才适合扩大到完整规划单元和长篇成本验收。

## 复现

```bash
set -a
source .env.local
set +a
.venv/bin/python scripts/run_real_generation_probe.py \
  --release-region overseas --script-reasoning-effort medium \
  --episodes 3 --max-provider-requests 6 --deadline-seconds 900
```

`--script-reasoning-effort` 只改变当前探针进程。脚本记录源码哈希、固定输入、实际请求、原始正文、连续性报告、双语检查和 token 用量。已完成集可用 `--verify-replay --output-dir <目录>` 在新进程内零模型请求复核；本项不等同于未完成流的断点续传。
