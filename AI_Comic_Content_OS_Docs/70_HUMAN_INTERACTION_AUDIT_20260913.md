# 全流程人机交互检查，2026-09-13

## 结论与范围

创作输入、总纲、剧情规划、路线图审核、正文生成、编辑保存和导出，已用《回执之前》八集案例在桌面和手机分别跑通。分镜另用《门后的钥匙》两集两场案例测试编辑、候选、版本、失败恢复和导出，并修复发现的问题。

当前结论是已覆盖交互通过，不代表所有功能细节或创作质量全部验收。完整流程连接 `3006 -> 8004` 本地离线服务，没有浏览器 API 拦截；该服务返回演示内容。分镜的失败注入和候选操作使用浏览器 API 固定数据，不能证明真实模型能完成分镜生成。

测试自动点击审核按钮，是为了验证状态流转，不构成人工内容批准。

## 已修复问题

1. 分镜选集只存页面状态，刷新或返回正文可能回到另一集。切换现在同步项目的当前集数。
2. 各场共用修改要求，切换场次会把要求带给另一场。现在按场分别保留，同一集内来回切场不会串用。
3. 场一候选异步返回时，正在阅读的场二也可能显示候选状态。现在候选状态限定在对应场次。
4. 历史分镜使用当前正文作为场景标题和摘要。现在读取该版本绑定的正文快照，并保持只读。
5. 加载失败被显示成尚未创建，可能引导用户重复编排。现在展示加载失败与重试入口。
6. 手机上保存失败提示可能落在视口外。现在错误滚动进入视口，保留编辑值，允许修正或重试。
7. 非法镜头时长等输入直接提交后才失败。现在按场和镜定位校验错误，时长字段显示错误，失败前不发送保存请求。
8. 编排中点击正文等站内链接可直接中断页面。现在拦截该离开操作并提示等待或暂停；暂停在当前场保存后生效，续编跳过已完成场。
9. 路线图生成提示与尚待作者批准的状态冲突。中英文提示都明确等待审核。
10. Markdown 分镜导出遗漏每场待确认事项、镜头声音和作用。现在保留这些内容及锁定状态、设计字段名称；下载内容已断言验证。
11. 执行摘要在没有角色引用但对白有姓名时仍显示人物不明确。现在可从明确的对白姓名回填；摘要默认折叠，减少手机翻页。候选与当前分镜的待确认事项直接显示在镜头前。
