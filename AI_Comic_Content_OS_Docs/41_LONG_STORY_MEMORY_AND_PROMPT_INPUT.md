# 20 万字长篇记忆与生成前上下文

日期：2026-09-08（Asia/Shanghai）。承接第 40 号报告。用户要求先整体审查记忆系统，再优化，并明确最多 20 万字；创意质量、一致性和连续性优先，速度也重要，不考虑 token 消耗。

## 整体链路与判断

现有系统已有分层保存、结构化状态、来源和按集召回，不需要另起一套向量数据库或新增模型摘要环节。主要问题是状态保存及上下文整理过程丢失了生成所需的信息。

| 环节 | 当前实现与审查结论 |
| --- | --- |
| 原文与版本 | Episode Artifact 保存完整正文和来源，Workspace 保存当前工作稿；确认稿、派生状态、临时稿分层。原文是重建依据，不能以摘要覆盖。 |
| 权威记忆写入 | 只有 canonical 制品能推进正式事件和 Continuity Ledger；修订候选保持 provisional。正式账本支持重放和回滚。 |
| 工作记忆更新 | 前端按已保存各集重建人物、世界状态、关系、故事线和伏笔。人物知识按稳定键更新；此前仅保留最近 30 条，后端账本仅 50 条。 |
| 本集召回 | 按人物、故事线、伏笔、时间范围选择记录，保留来源和权威性；此前人物知识仅取前 5 条且去掉键名。 |
| 上集交接 | 此前只拼结果和状态摘要，未传最后一场实际动作与对白；具体距离约定因此丢失。 |
| 最终提示编译 | 有 memory_recall 时省掉旧 checkpoint，导致仅存在于 checkpoint 的知识键也被省掉；handoff 再次截短。 |
| 修改早期集 | 召回过滤未来记录，并可用原请求的历史召回补缺；人物按现存正文重建。此前世界状态仍合并旧投影，修订删除的事实可能残留。 |
| 运行检查 | 确定性检查不等同于作品语义验收。改进重点是生成前事实完整性，不增加每集模型审稿或自动整集重写。 |

## 本轮优化

1. 人物知识保存取消前端 30 条、后端 50 条截断；正式账本上限与系统 2000 集、每集最多 20 个知识更新的契约对齐为 40000 条。当前知识键被更新时移到最近位置，旧值由新值替换。原集正文仍保存原始证据。
2. 知识记录补充确定性来源集数和证据场次；这些信息由投影填写，不要求模型猜测。新字段兼容旧记录。
3. 召回胶囊通过结构化 `knowledge_states` 和 `active_constraints` 传递知识键、陈述、认知状态和来源，不再只取前 5 条并揉进摘要。已选关键事实不受摘要字符压缩影响，也不挤掉其他支持性胶囊的预留空间。
4. 后端提示编译保留以上结构化字段。兼容旧召回包时，只从同为 provisional、同一集边界、早于当前集的 checkpoint 补齐缺失的知识键索引；已有结构化人物知识不重复补入。
5. 产品与实测探针共用 `episode-handoff.ts`，按现有正文排序函数带入最后一场实际动作和中英对白，明确作为已发生事实承接。后端允许最多 24000 字符交接并取消二次截短，不默认重新生成摘要。
6. 修订世界状态时，现有正文替换相同集数的旧派生历史，已删除的事实不再残留。保留其他集证据及作者附加信息。
7. 恢复工具继续验证历史文件、请求指纹、规划、制品和保存内容；已明确登记源码变化时，仅允许 memory_recall、provisional_continuity_checkpoint 和 previous_episode_handoff 重新投影。历史 request.json 保持原证据，当前投影另存 reprojected_request.json；批准规划变化仍拒绝。

整个优化没有新增向量服务、模型摘要调用、模型审稿步骤或后台任务。

## 容量与完整性证据

合成样本包含 120 集、精确 200000 个正文字符。通过实际 TypeScript 产品投影，保存并召回首集至第 120 集的全部 120 条人物知识，首集访问约束仍可召回，来源集数保留，输入正文未改变。一次测得投影约 28 毫秒、召回 JSON 23927 字符；这是本机合成样本测量，不是服务时延承诺。

另有 121 集回归验证：旧键更新为 disproved 后只保留新状态，早期其他键仍存在；撤回最后一集中的该更新并重建后，原始已知状态恢复。后端 ledger 序列化读回也保留全部键。API 拒绝把未来知识藏入较早来源的胶囊，前端原有按集过滤和修改集召回测试继续覆盖未来信息隔离。

这些验证证明此次记忆保存、重建和输入传递能处理所测的 20 万字规模，不代表已用模型创作并验收整部 20 万字作品。长篇故事的事实密度、人物数量和伏笔复杂度仍影响召回质量；生成仍按当前集的批准人物、故事线和伏笔选择记忆。现有最多 50 个胶囊与 4200 字符 QC checkpoint 是不同的有界视图，不能宣称完整账本都进入自动 QC。
