## 保存边界

1. 分集列表和连续性输入在函数式更新内部读取最新项目。每次只追加新完成的一集，保留其他分集、其他批次以及作者对人物、剧情线和关系的修改。
2. 已提交的相同分集 ID 保留当前版本，后续提交及批次收尾不会重新覆盖其正文、候选、锁定状态或编辑标记。同集号出现其他 ID 时报告冲突，不把对方正文当成自己的结果确认。
3. 更新执行时检查完整任务快照和来源总纲版本。任务更换、检查点变化、总纲升级及项目删除均中止旧提交。
4. 批次统计依据最新合并结果，包含恢复前已经保存的分集；批次创建时间和原始生成指令得以保留。完成前复用现有缺集检查，删除过的正文不会被结束保存重新带回。
5. 首批的旧版单集字段只在首次追加且没有旧生成记录时初始化。续写完成仍默认定位本批首集，但保留生成期间已经改变的分集选择。
6. 两条入口都在正文及批次保存成功后才完成检查点。保存失败不自动重试模型；首批错误处理中的补记失败也不会阻断任务释放或掩盖原始错误。
7. 新增正文时调用现有 `synchronizeContinuity`。相同结果的重复提交和批次结束仅更新批次状态，不重复计算整套连续性。没有测量或宣称端到端模型生成速度提升。
