## 范围与职责

新增 `frontend/lib/script-generation-session.ts`，统一首批生成和续写中的检查点保存、暂停门禁、单集请求取消与有界重试。两条入口继续负责规划门禁、模型请求参数、生成窗口、分集结果提交和界面进度，通过同一个会话模块协调恢复状态。

- 检查点继续调用 `saveGenerationTaskOnServer`，采用服务端返回的已协调版本；服务端不可用时保留原有本地检查点兜底。每次转换只写一次大工作区。
- 现有服务端队列负责 API 请求版本协调；会话队列覆盖服务端响应到浏览器保存的完整转换，使后续状态变更基于刚保存的检查点计算，避免并发回调丢失完成记录。
- 单集重试复用 `generateWithAutomaticTransientRetry`、原次数上限、退避和错误分类。暂停恢复时使用新 AbortController 和原 Agent 请求 ID，继续复用后端检查点。
- 暂停通知和自动重试进度由工作区回调展示，模块不依赖具体界面组件。模型适配器、提示词、API schema 和后端持久化没有修改。
- `useScriptGenerationRecovery` 在浏览器生成会话活动时不抢先完成其检查点，待会话退出后再处理遗留任务。

主工作区从 3160 行降到 2993 行。新会话模块 143 行，已有恢复 Hook 从 140 行变为 141 行，生产代码合计净减少 23 行。没有测量或宣称端到端生成耗时改善；本轮收益是重复编排减少、恢复状态集中和保存边界修复。

## 修复的边界

1. 用户在“暂停”检查点保存期间快速继续时，即使浏览器暂停门禁已经释放，持久化状态也会恢复到 running，不再遗留 paused。
2. 多个请求同时响应暂停时共用一次状态转换和恢复门禁；恢复后仍分别使用各自稳定的 Agent 请求 ID。注册在暂停之后的请求沿用现有取消防线。
3. 检查点写入前及 React 更新函数执行时复核当前任务。任务替换、检查点更新或项目删除后，迟到的保存结果不能覆盖最新记录。完成清理同样只作用于自己的检查点。
4. 本地检查点写入失败会抛出不可自动重试的持久化错误；首批与续写都在模型调用前停止。结束记录保存失败也会报告错误，并保留再次提交的能力。
5. 错误处理阶段保存失败检查点属于尽力记录，不再让第二个保存异常中断原错误展示和浏览器任务释放。用户可读会话错误复用工作区现有错误显示入口。
6. 状态转换队列在一次写入失败后仍可继续处理后续重试。React 更新重放不会重复计算新的检查点版本。

检查点的静态规则只处理身份、版本、状态和重试边界；剧情质量仍由现有模型服务判断，作者确认机制和 Agent 服务复用关系保持原样。本轮没有新增 Agent、Skill 或模型调用层。
