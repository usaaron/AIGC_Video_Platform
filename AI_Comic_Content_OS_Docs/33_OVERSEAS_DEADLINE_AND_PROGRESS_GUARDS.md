## 累计预算的实际范围

新增 `llm_deadline.py`，使用单调时钟和请求上下文保存绝对截止时刻。内层预算不能延长已有父预算。通过同步 HTTP/1.1 网络读写包装，在每次底层读取、写入、连接和 TLS 操作前重新限制剩余时间，返回或失败后再检查截止。因此持续注释行、慢滴响应头、没有换行的正文不能靠反复刷新 socket 空闲超时无限延长本次操作。

| 层级 | 配置与默认值 | 覆盖范围 |
| --- | --- | --- |
| 路线请求操作 | 对应角色的 `REQUEST_DEADLINE_SECONDS`；省略时沿用该角色解析后的 `TIMEOUT_SECONDS` | 一次流式或非流式适配器操作，包含其内部传输重试；Key 池还包含排队和换 Key 尝试 |
| 初稿生成链路 | `LLM_INITIAL_GENERATION_TIMEOUT_SECONDS`，默认 900 秒 | 初稿主请求、初稿格式修复、同阶段重新生成及非流式恢复，共享剩余预算 |
| 隔离探针整轮 | 现有脚本的请求次数上限和进程 watchdog | 独立测试进程；本轮没有启动真实探针 |

海外可分别设置 `LLM_OVERSEAS_SCRIPT_REQUEST_DEADLINE_SECONDS` 和 `LLM_OVERSEAS_SCRIPT_REPAIR_REQUEST_DEADLINE_SECONDS`，按现有角色配置回退规则解析。它们是累计秒数，与 socket 空闲超时不同。初稿链路 900 秒不代表完整单集的后处理、所有编辑阶段或后台任务都有统一 900 秒上限。

到达任一有效累计时限时，当前调用产生 `LLMRequestError(category="deadline", recoverable=False)`：不接受迟到结果，不继续换 Key 或启动恢复请求。仍在预算内的普通断流可以按原有规则恢复，但只能使用父链路剩余时间。原有模型、推理强度、密钥和 `.env.local` 内容未改；未显式配置新变量的路线也会获得上述默认累计上限。

Key 池等待也受预算约束，到限不会抢占其他调用的槽位。现有 hedge 路线继承父上下文；主等待到限会设置取消信号，子路线在其检查点或受限 I/O 返回时停止，不承诺其他线程在同一瞬间退出。

## 故障保存与前端行为

初稿链路到限会传播到 Agent，由现有失败持久化机制保存 `failed`，不能将不完整或迟到 JSON 写成成功检查点。

普通 API 返回 503，并显式设置：

- `X-Generation-Retryable: false`
- `X-Generation-Failure-Class: time_budget_exhausted`
- `X-Generation-Error-Type: local_deadline_exceeded`

SSE 返回 `error_type=local_deadline_exceeded`、`recoverable=false`。前端已有的显式不可重试处理会停止自动重试。该错误不会被标成用户规划输入问题，也不会被此前的结构化输出错误覆盖。作者可在检查服务后主动重试，此前保存的结果仍保留。

## 内容无关的进度记录

`llm_stream_progress.py` 记录每笔尝试的 HTTP 状态、响应头、首字节、首段文字、首段可见推理、最后字节及最后文字的相对时点，以及响应体字节数、解析事件数、SSE 注释行数和文字/可见推理字符数。关键首次事件即时记录，有新字节且距上次记录至少 30 秒时再记录活动快照，关闭时补最终快照。

该进度载荷没有正文、提示词、密钥、供应商原始事件内容或任意事件类型。沿用路线日志的项目、集数、阶段和 run 标识，探针现有脱敏落盘器可直接保存。探针 manifest 新增时限环境覆盖值及新增模块源码指纹；值为 null 表示没有显式环境覆盖，不表示预算为零。

计数不是计费用量：文字字符包含 JSON，不能当有效剧本正文；可见推理字符为零不代表没有内部推理 tokens；注释行也不一定是供应商心跳。记录是活动驱动，没有新增后台定时器，完全停流期间不会每 30 秒主动写一行；最终时限错误与最后活动时点用于定位停顿。响应体读完也不代表模型生成成功。

## 限制与下一动作

HTTPX 没有公开的同步 network backend 注入接口；包装在新 Client 建连前安装到默认及代理传输，限定 HTTP/1.1，并对私有结构做显式校验。当前验证版本为 HTTPX 0.28.1 / HTTPCore 1.0.9，`httpcore>=1.0,<2.0` 已成为直接依赖。后续依赖升级需重新验证此接点；遇到不支持的结构或 HTTP/2 会明确拒绝安装。

底层 DNS 解析、多地址连接的内部执行和同步自定义回调不能被这层强制打断，只能在返回后检查。自定义 transport 的内部 I/O 也不由 HTTP/1.1 包装控制。这不是完整作业的进程级硬中止，远端收到请求后的取消与计费不能由本地超时保证；未知 usage 仍须保留为未知。

下一动作是把第 32 号记录的测试规划歧义单独修订为新版本，再进行新保护下的海外单集有界验证。预算沿用用户已授权的最多 6 次物理请求、整轮最多 15 分钟，不把剩余额度当成必须耗尽的目标。明确记录正文主角色及恢复角色各自参数；只有单集完整通过后再恢复三集验收。历史基准和失败样本保留，不将本轮离线通过写成海外生成质量通过。
