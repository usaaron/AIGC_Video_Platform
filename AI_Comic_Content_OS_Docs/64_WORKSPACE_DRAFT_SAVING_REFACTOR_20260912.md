## 范围与职责

新增 `frontend/components/use-script-draft-editing.ts`，负责正文内联编辑缓存、立即写入项目草稿、显式保存及已审阅候选提交。新增 `frontend/lib/script-draft-state.ts`，集中既有分集生命周期、锁定判断、正文读取优先级、已保存门禁和正文改变后的失效字段。

- 内联编辑仍立即调用现有 `updateProject` 写入浏览器草稿，不调用模型或产物存档，也不重复重建连续性。
- 手动保存仍先调用现有 `reviewEpisodeDraft`，再提交审阅后的正文；修改候选沿用已审阅结果，深化候选沿用原审阅步骤。
- 三条保存路径共用 provisional draft 产物存档、目标分集更新、旧候选/修订/终稿状态失效和连续性同步。复用现有服务、状态 Provider 和产物接口，没有新增模型或持久化层。
- 候选尚未采用时的状态更新可继续跳过连续性重建；共享更新入口使用最新项目的分集列表，保留其他分集的后续变更。
- 创作输入表单的 `project-draft-autosave` 仍属于独立表单流程；正文手动保存包含审阅和存档，未将这两种不同语义混成一个保存动作。

## 修复的边界

1. 审阅或产物写入期间，正文、锁定状态、规划、候选或目标分集发生变化时，旧结果不能覆盖最新内容；整项目被删除也不会误报保存成功。
2. 同一集的重复手动保存复用进行中的请求，避免重复审阅和存档；失败后可再次提交。
3. 编辑缓存按项目隔离；旧项目保存结束不能清理新项目同集号的草稿。较新的内联编辑也不会被旧保存回调清除。
4. 本地保存失败时恢复未保存的来源正文或候选及原产物引用，保留重试入口，避免在内存中错误显示已保存并开放交付。恢复前复核提交内容快照，保护保存期间的新改动。
5. React 会重放状态更新函数，因此失败恢复不再依赖提交对象的引用相等。内容快照忽略更新时间，保留实际分集内容与状态比较；没有额外持久化版本字段。
6. 保存协调抛出的用户可读错误使用独立错误类型展示；API 错误仍经过既有错误转换，不修改并行任务负责的 `api-error.ts`。

服务端产物写入与浏览器项目提交仍不是跨端事务。来源在存档期间变化时，已写入的 provisional 产物可能保留，但不会被绑定到最新分集；本步不删除远端历史产物。
