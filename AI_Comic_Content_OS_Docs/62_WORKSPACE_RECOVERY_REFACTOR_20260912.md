日期：2026-09-12。承接 [统一集成验收](60_UNIFIED_INTEGRATION_ACCEPTANCE_20260912.md)，属于 [核心服务渐进拆分](56_CORE_SERVICE_REFACTOR.md) 的第十步。

## 范围与职责

从 `frontend/components/script-workspace.tsx` 提取自动续写、恢复任务完成收尾和中断恢复三个 effect，新增 `frontend/components/use-script-generation-recovery.ts`。

- 自动续写与中断恢复共用定时调度入口：启动前去重、取消未执行的定时器时释放标记、启动后保持去重，覆盖 effect 重放和切换项目。
- 三处覆盖检查复用当前分集编号列表；分集数量相同但编号改变时仍重新判断缺失范围。
- 自动恢复保留原指令、分集范围和退避时间；空工作区使用原首次生成入口，已有正文使用原后续生成回调。
- 继续复用 `generation-recovery`、`episode-generation-planning` 和 `project-sync`。Hook 不实现模型调用、生成循环、检查点格式或新的重试机制。

修复了完成收尾的竞争条件：写入完成状态前检查当前任务 ID 和版本；服务端保存返回后，只清理同 ID、同版本且仍处于完成状态的本地任务。旧请求迟到时不会清掉新任务或更新后的检查点。保存失败时保留旧逻辑的本地完成清理语义，但失败会被处理，不产生未捕获的保存拒绝。

主工作区由本步开始时的 3834 行降到 3719 行，新增 Hook 140 行，生产代码合计增加 25 行。收益是职责集中、调度重复减少和竞争修复；不把迁出的 115 行计作总代码删除，也未测量或宣称端到端生成提速。工作区的生成会话、草稿保存和作者候选协调仍待后续拆分。
