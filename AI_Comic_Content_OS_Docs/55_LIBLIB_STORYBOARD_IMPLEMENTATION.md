# Liblib 借鉴与文字分镜实现核对

日期：2026-09-11（Asia/Shanghai）。

## 1. 原先完成到哪里

用户指出“看不到分镜”是准确的。此前的 Liblib 融合主要是 [44 号方案](44_PREPRODUCTION_STORYBOARD_PLAN.md)、分工和路线图的文档整合。已有正文场景清单、动作对白顺序、连续性记录和制作索引，是可以复用的基础，不能算作独立分镜功能。

本轮开始实现可运行的文字分镜。参考依据仍是原对话及 [Liblib 阅读笔记](../libtv-mishou-iii-notes.md)，没有重新核验原站全片，也没有把原作品剧情、角色、画幅或时长写成项目默认值。

## 2. 借鉴与实现对照

| 参考方法与需求 | 本轮实现 | 仍需完成 |
| --- | --- | --- |
| 视觉方向、场景设计、逐镜执行分层 | 本集视觉方向；场景空间、信息揭示、动作节拍、转场；镜头摄影、动作、声音、起止状态 | 项目级 VisualBible、跨集继承及版本依赖 |

| 人物、地点、道具和变体复用 | 当前摄影文本包含原文人物和状态，尚无独立生产资产库 | 稳定资产身份、角色/服装/伤势变体、设计版本与占位符 |
| 局部改稿与版本保护 | 直接编辑、拆镜、合镜、排序、整镜锁定、场级修改指令、当前/候选切换和采用/放弃 | 字段级锁定；保留锁定镜头时仅重编其余镜头；并列差异视图 |

本轮不增加图片、视频或音频生成。系统与下游团队的原分工保持有效。

## 3. 当前可用流程

有一集完整正文即可打开项目的“分镜”栏目，选择集数并主动编排。页面进入和集数切换不会触发模型。全集编排逐场保存，可以在本场完成后暂停；重进后从已保存结果继续。单场失败保留此前场景。

每镜默认显示画面动作和原文对白；摄影、来源及视频描述按需展开。修改保存后更新编译描述。拆镜的中间状态需要人工复核，会记录待确认事项。撤销按钮恢复本次尚未保存的编辑，历史版本可只读查看；尚无任意历史版本一键恢复操作。

重编已有场景先形成候选，由用户选择是否采用。来源相同且引用分组相同的镜头保留 ID；来源改写后重新生成的镜头获得新 ID。锁定保护镜头内容和位置，必须先单独解锁才可改动。当前整场重编遇到锁定镜头会阻断。

正文更新后必须显式更新分镜来源。变化场景保留旧镜头及旧正文绑定，新的编排形成候选；采用后才解除该场的过期标记。摄影内容不会写回正文 Artifact 或推进叙事连续性账本。

## 4. 实现与持久化

- 后端：`backend/app/modules/preproduction/{models,repository,service}.py` 和 `backend/app/api/routes/preproduction.py`。
- 前端：`frontend/components/storyboard-workspace.tsx`、`frontend/lib/storyboard.ts`、`/projects/[projectId]/storyboard`。
- 复用现有 `ModuleDocumentRecord`，命名空间为 `preproduction_storyboards`。每集一个最新版本记录和追加式历史记录，同一事务保存；不增加重复仓储框架或数据库迁移。
- 更新必须携带 `expected_revision`，过期写入返回 409。保存时检查项目仍存在，永久删除项目在同一事务清理分镜最新版本与历史记录。
- 模型复用规划编辑器的统一协议适配和配置，当前为 DeepSeek V4 Pro。没有新增通用 Agent、聊天记忆或另一套模型路由。
- 单场一次有界结构化调用，再做确定性的来源检查及提示词编译。未增加默认逐镜多轮审稿。
- 前端代理等待上限调整为 660 秒，解决 Next 默认 30 秒超时早于单场模型返回的问题；模型自己的请求时限仍有效。

分镜当前是同步单场请求与持久化场级结果，不具备后台 worker 租约或无人值守调度。页面关闭后在途请求可能继续保存本场，后续场不会自动启动；重新加载读取保存结果。并发写入有版本保护，但并发生成还可能产生重复模型调用。
