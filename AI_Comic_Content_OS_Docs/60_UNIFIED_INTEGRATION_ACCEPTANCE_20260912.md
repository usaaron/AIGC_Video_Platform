## 新增贯通覆盖

- `tests/test_author_revision_workflow.py` 新增 2 项。通过真实修改审核 HTTP 接口生成报告，写入临时 SQLite，再由新服务实例通过修订 HTTP 接口读取。确认原项目、总纲和正文不被覆盖；同一确认重试只生成一次；审核后工作区发生变化时返回 409，且不创建修订项目。
- `tests/test_input_source_workflow.py` 新增 2 项。上传资料经真实识别 HTTP 接口得到精确引用，再进入真实灵感接口；正常模型响应与无效模型响应恢复都保留原文人物目标、结局及作者暂缓的决定，不把识别结果写成批准状态。
- 模型使用固定离线适配器，接口校验、服务逻辑、持久化与事务使用实际实现。浏览器使用隔离 3003 服务和 API 模拟，两类测试覆盖互补，不将模拟接口称为真实模型验收。

## 验收修正

- 状态门禁夹具明确提供 `assessmentVersion=2` 和逐集结构齐备标记。旧版 `missingItems=[]` 仍不能自动准备整剧规划。
- 候选刷新夹具按实际设置归一化规则计算输入签名，并提供项目列表的 `content_spec_id`。缓存的资料核对结果符合当前协议，不让与该用例无关的开发模式请求取消干扰候选验证。
- 首次候选刷新检查请求中当前问题携带的旧选项；累计候选历史仍由现有替换逻辑与相邻单测覆盖。503 恢复断言使用应用实际保留的安全错误文本。
- 浏览器健康检查可以显式声明错误场景中预期的完整响应记录，严格比较状态码、方法、URL 和次数。额外 5xx、JavaScript 错误和失败请求仍使测试失败。

## 运行核验

共享后端由输入识别任务在双方确认后统一重载，最终 8000 进程为 39225。该任务确认用户工作区 revision 8 及完整数据 SHA256 在重载前后不变。本任务独立复查 `/health/live`、`/health/ready` 均为 200，数据库和主机授权就绪，项目 6 个、策略 4 个；3000 前端入口返回 200。

输入识别任务另完成真实 DeepSeek-v4-flash 与浏览器复测：目标 8 集、8 个集号中只有 1 集字段齐备，明确列出第 2 至 8 集缺口；桌面和手机核对区无横向溢出，未确认创建测试项目。详见 [文档 59](59_INPUT_READINESS_AND_SOURCE_HANDOFF_20260912.md)。本任务人工复核了作者冲突窗口的桌面及手机截图。

本轮没有调用真实模型重新生成整部剧本或真实上游修订，不据离线结果推断所有语义冲突都可被识别。上游修订仍通过独立项目重新确认完整规划，尚未实现按依赖自动重算部分后续集。
