## 修复的边界

1. 修改返回及实际写入时同时复核请求身份、分集身份、锁定状态、正文/规划来源和完整待处理决策。作者更换审阅、调整方向或撤回要求后，旧结果不能覆盖新状态。
2. 项目切换或组件卸载会取消原请求；不同项目的会话记录独立恢复和保存。切换分集后，仍有效的结果写回原分集，消息与视图不会跳到错误分集。
3. 新请求替代旧请求后，旧回调不能写入候选或追加虚假的暂停提示。取消发生在函数式更新执行前时，同样禁止结果落盘。
4. 冲突动作重复点击只执行一次。修订请求身份和完成时间在 React 状态更新函数外创建，避免更新重放产生不同结果。
5. 暂缓或撤回的本地保存失败时，恢复原待处理记录并允许重试。恢复前比较刚提交的内容，保护期间发生的较新变更；过期撤回不会误报成功。
6. 确认前核对选项 ID、类型和方案；补充方向必须重新检查。源同步完成后再次核对正文、规划和作者决策，最后绑定修订版本时也复核原决策，避免迟到结果覆盖最新选择。

远端修订创建、同步和浏览器保存仍不是跨端事务。中途失败沿用原请求 ID 重试恢复；已创建的远端修订不会因原项目后来发生变化而被删除。本步没有修改模型配置、API schema、后端持久化或修复预算，也没有运行真实模型调用。
