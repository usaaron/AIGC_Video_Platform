# 公共提示层与分镜

本页解释会与各阶段提示共同生效的内容。整理对象为当前工作区源码中的定义，运行数据库中的模板值未另行核实。以下是现状说明，尚未按这次问答修改任何生成规则。

## 1. 一次生成会收到哪些内容

规划阶段大致由“阶段主提示 + 项目市场规则 + 用户与已批准资料 + 作者决策记录 + 按条件选择的创作知识 + 输出结构”组成。具体分支以[规划导览](02-planning.md)为准。

正文阶段先按策略的 `prompt_ids` 取出 Prompt Library 模板，再由 `TemplatePromptBuilder` 叠加单集规划、场景执行蓝图、记忆、人物状态、语言格式与修改指令。最后，模型适配层提供系统角色及 JSON 输出结构。参见 [prompt_retrieval.py](/Users/simonriley/Downloads/docs/backend/app/modules/script_engine/prompt_retrieval.py:43)、[prompt_builder.py](/Users/simonriley/Downloads/docs/backend/app/modules/script_engine/prompt_builder.py:56)。

因此，主提示、知识条目、修复提示都有可能约束创作。后续讨论修改某条边界时，应查明所有重复表达它的位置。

## 2. 作者意图与授权

[正文工作区前端的作者意图前缀](sources/shared-frontend-author-rule.md)明确写“用户明确表达的意志、选择、修改和否决永远优先于系统建议、模板和模型推断”，同时要求未明确的内容保持待定。它会与后端的修改合同共同进入生成请求；不能只看到这个前缀，就认定后端已经实现冲突后由用户选择的完整流程。

[作者决策合同原文](sources/shared-author-decisions.md)区分已确认事实、作者修订、待定项与授权项：

- 已确认事实要保持语义；作者较新的明确修订可以优先于旧输入。
- 未决身份、背叛、死亡、反转、关系结果与结局，不得由模型静默决定。
- 授权受记录的权限范围限制；`suggest_only` 只能提出候选，经过作者保存确认才成为依据。
- 结构推导可以安排篇幅、节奏位置与审核点，但不得暗中决定剧情。

这些已经保护了作者的控制权，值得作为后续优化的基础。“没有填写”与“明确不授权”现在受到较接近的限制，与本次允许 AI 补全留白的讨论需要进一步对照；本页不替用户决定如何改。

## 3. Prompt Library 的内置原文

### 大陆路径

[两个完整模板](sources/library-mainland.md)的核心现有要求：

> 根据结构化创作意图和已批准单集线路图，生成中文连载漫剧的单集正式可拍摄剧本正文。

模板接着要求遵守线路图、保持人物与世界一致、场景有目标和阻力、结果影响后续；避免 TikTok 或固定付费卡点规则、重复冲突、空转场景和无依据反转。

其中一个模板的类型叫 `story_planning`，但这里实际参与正文生成。总纲阶段另有专门的主提示，不能只按模板名称判断用途。

### 海外路径

[两个完整模板](sources/library-overseas.md)要求较强的开场吸引力、主角主动性、场景因果、结尾续看动力、可表演和便于字幕呈现的短对白。原始模板带有 TikTok、美国年轻女性及言情标签，这是该内置模板的既有定位，不是本次建议所有题材都照此执行。

该函数位于 `run_real_generation_validation.py`，但确实被[启动资源生成逻辑](/Users/simonriley/Downloads/docs/scripts/bootstrap_frontend_mvp_runtime.py:220)使用，因此不能简单归为失效的测试示例。

以上均是源码中的启动定义。运行时取的是策略声明的模板 ID；若运行库有其他版本，应在实际修改前核对目标版本。

### 默认关闭的增强模板

[Creative Deepening 原文](sources/library-deepening.md)属于保留兼容能力。现有项目文档明确当前默认关闭，不是每集正文的固定步骤。

## 4. 市场、语言与交付

[市场合同原文](sources/shared-market-contracts.md)和[海外语言合同](sources/shared-overseas-language.md)按项目市场生效：

| 路径 | 现有要求 |
| --- | --- |
| 中国大陆 | 创作者可见字段、人物名、规划和对白使用简体中文，并遵守大陆语言文化背景。 |
| 海外 | 创作者阅读的总纲、规划、动作和表演意图仍用中文；面向观众的对白使用自然英文，并保留既有中英交付形式。项目未选国家时，不擅自设定具体国家。 |

[当前交付常量原文](sources/shared-delivery-numbers.md)：单集 75-115 秒，偏好 90-105 秒；1-5 场、25-35 条对白、15-20 个镜头单位，另有系列时长与交付格式版本。各阶段按不同方式引用这些数字；它们是当前产品的交付要求，不能宣称是短剧市场的普遍规律。正文中的镜头单位预算也不等于分镜功能已实现。

## 5. 静态创作知识

[知识目录原文](sources/shared-knowledge-catalog.md)包含 12 条知识与 5 个知识包。每条不只有“原则”，还包括适用规则、限制条件、反例和来源记录。选取机制见[知识包选择原文](sources/shared-knowledge-selector.md)。目录不是每次全量注入，主流程按策略和阶段选择；规划还会按任务过滤。

| 现有知识主题 | 原文中值得保留的边界 |
| --- | --- |
| 暗黑爱情 | 仅在用户明确要求且有内容边界时使用；伤害或控制不是必需桥段。 |
| 选择塑造人物 | 用行动与后果表现人物；不要求每个选择都极端、不可逆。 |
| 冲突与代价 | 通过信息、关系、风险等多种方式升级；允许阶段性释放。 |
| 因果链 | 后续事件由先前状态变化推动；允许有明确组织逻辑的留白与联想结构。 |
| 开场吸引力 | 让观众理解为何继续看；不把广告时点当所有虚构故事的规律。 |
| 铺垫与兑现 | 结果有前因、形式可意外；兑现可以有代价，也可以悲剧。 |
| 场景与可见动作 | 交代必要的空间、时间，把内在状态转化为可表现的行为。 |
| 观众参与 | 让观众从行为推断意义，避免把所有情绪直接解释出来。 |
| 表达通道 | 区分动作、对白、旁白、内心与屏幕文字。 |
| 单集推进与长篇持续性 | 每集形成可观察的变化和续接点；改变策略、信息、关系和代价，避免长篇只不断增加集数。 |

当前大陆默认知识包为 `knowledge_bundle.draft.cn_mainland_serial_short_drama.v1`，含 10 条；旧 `longform_foundation.v1` 和 `planning_candidate.v2` 目录中映射到相同的 10 条。海外暗黑爱情知识包的使用仍需满足其适用条件。

## 6. 模型外层指令

[Chat 系统指令](sources/shared-chat-system.md)、[Responses 系统指令](sources/shared-responses-system.md)与[JSON 结构合同](sources/shared-json-contract.md)约束返回合法的结构化对象、字段类型及根对象形状。它们服务系统读取与交付，不是故事审美标准。调用使用哪一种由实际传输配置决定。

## 7. 分镜现状

目前只有[既有分镜设计方案原文](sources/storyboard-existing-plan.md)，尚无主流程可调用的正式分镜提示词。

已有设计明确了：从用户选定正文版本生成视觉方案、文字资产设计、镜头、图片与视频提示词；摄影设计不能新增已经发生的剧情事实；未规定的外观细节标为建议；发现正文缺口时提出修订候选，由用户采用；实际图片、音频、视频生成及剪辑由下游负责。

这些是后续分镜工作的既有基础，本轮只归档，不将未实现设计伪装为已运行提示，也不新增分镜模板。
