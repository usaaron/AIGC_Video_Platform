## 当前工作流怎样分工

| 阶段 | 当前实际承担的工作 | 已有内容中值得保留的部分 |
| --- | --- | --- |
| 输入想法 | 接收创作描述、标签、人物、参考资料；识别已有内容完成度。 | 区分从零创作与高完成度原文导入；导入原文保留供核对。 |
| 补充细节 | 自主填写，或由 Grill 追问当前真正需要决定的问题。 | 问题有依赖关系、历史问题去重、尊重暂缓与明确授权、参考资料按用途使用。 |
| 生成可修改大纲 | 组织整部故事的前提、人物、世界、关系、故事线、升级阶段、结局方向、伏笔和禁区。 | 用户已定事实保护；不复制参考剧情；识别已有支线；大纲仍需保存与确认。 |
| 拆分剧情部分 | 把已批准故事组织成可变深度的剧情树，再逐级展开。 | 不固定四等分；节点交代因果事件链、局部结算和后续承接；按故事容量估计范围。 |
| 单集规划 | 把叶节点展开到逐集目标、进入状态、冲突、选择、结果、退出状态与结尾承接，并准备场景执行蓝图。 | 承接已批准事件与伏笔；防重复；以场景蓝图降低正文模型重新猜剧情的需要。 |
| 剧本正文 | 把已批准线路图和场景蓝图写成可表演、可拍摄的动作与对白。 | 不重新规划核心事件；角色知情有来源；动作有前因后果；禁止为凑数套统一节拍。 |
| 分镜 | 现有文档已定义视觉、资产、镜头、图片和视频提示词的职责。 | 属于待实现设计；正文版本是来源，视觉设计不静默新增剧情事实。 |

这里的分工是源码归纳，不意味着每一步都对应单独的一条模型调用。例如：通常的技术根节点可以直接从已确认总纲编译顶层分支；有些检查只是本地规则；失败时又可能追加修复调用。具体情况见各节。

## 已有提示词不是一份孤立的文本

正文会组合策略指定的 Prompt Library 模板、结构化项目资料、已批准规划、场景执行蓝图、人物与连续性记忆、市场语言规则、格式要求和按条件选择的知识。规划阶段也会注入公共合同与任务知识。

所以，后续调整会以“某个具体要求”为单位核对主提示、共享知识及修复路径。例如：主提示已经反对统一节拍，备用修复中却可能仍出现固定循环；只改其中一处，模型实际收到的要求仍可能矛盾。

| 主题 | 现有内容 | 这次讨论需要对照的方向 |
| --- | --- | --- |
| AI 如何处理留白 | 作者决策合同禁止默认发明未授权的高影响事实；Grill 对“还没想好”保留待定。 | 用户允许 AI 在未指定部分创作。需要区分普通留白、明确保留、授权候选、已批准事实。 |
| 规划要做到多深 | 已有大纲、剧情树、逐集规划和场景执行蓝图；同时允许一些高影响项继续待定。 | 大纲写清结局与核心真相，规划协同把每集做深，减少正文返工；补齐时间点尚待逐项核对。 |
| 每集有什么价值 | 已有反重复、主角行动、局部兑现与后续承接；部分提示另要求不可逆或难撤销变化。 | 已同意允许信息、人物理解、情绪体验或期待变化构成观看价值。不能直接等同于每集重大事件或强反转。 |
| 节奏是否公式化 | 主提示与知识限制条款多处反对统一节拍；某些备用/修复提示仍规定较固定的循环。 | 保留短剧节奏和追看要求，逐条判断是否把结构要求扩大成剧情模板。 |
| 冲突由谁处理 | 连续性已有自动修复与阻断；正文修订有优先保留上游已批准约束的要求。 | 用户希望看到冲突提示后选择处理，创作需求优先；不能假定这套交互已实现。 |
| 分镜 | 已有独立设计方案。 | 后续沿用方案补充运行提示，不在本轮凭空生成并伪称已有。 |

## 资料边界与可核对性

- 这是当前工作区源码快照，包含尚未提交的既有工作；不是仅取 Git 已提交版本，也不是线上运行审计。
- 本轮未读取 `.env`、密钥或用户的运行数据库，未调用真实生成模型。Prompt Library 收录的是实际启动脚本引用的内置定义；运行库若有单独修改，正式调整前需再核对对应模板 ID 与版本。
- 动态项目输入、已批准剧情、记忆、检索资产、实际选中的知识、输出 schema 和开关会影响最终发送文本。本资料保留占位表达式，不伪造某次完整的最终 prompt。
- 原文条目包含当前适用状态。`active` 表示主流程存在调用；`conditional` 表示条件触发；`legacy` 表示保留入口但未见当前主前端使用；`disabled_by_default` 表示默认关闭；`planned_not_implemented` 表示设计未实现。其他更细状态以条目说明为准。
- 提取以 Python AST 定位定义，前端片段按已核对的行号定位。完整源片段保留原样，长文本阅读视图只为便于阅读，不替代源码中的拼装条件。
- [source-provenance.json](source-provenance.json)记录提取时间、每个源码文件和片段的 SHA-256，可用于之后核对是否发生变化。该记录不证明线上模板或所有分支都经过运行测试。

## 后续问答的使用方式

每次只拿一个现有条目讨论：先看它现在要求什么、哪部分已有价值，再提出具体疑问。确认后记录“保留、澄清、补充或局部调整”的范围，并核对引用同一规则的其他位置。

用户最早表达的“不喜欢烂大街、无亮点、糊弄观众”是审美动机；后续已明确不能把个人偏好直接升级为通用平台的剧情禁令。这份资料保留该区分。
