# 创作设定引导式流程

日期：2026-09-12。承接文档66的创作设定交互优化，与文档67/56的生成会话保存和恢复改动并行完成。

## 用户流程

创作设定现在只有三个明确步骤：

1. **补充想法**：用户可以直接写想法，也可以跳过。已有原文、标签和识别出的故事方向会同时作为当前基础，不要求用户重新填写。
2. **确认方向**：一次只显示一个待确认问题。用户可以直接填写、获取候选、补充条件或暂时跳过；问题下拉框保留跳转能力，但不再让多个问题卡片同时争夺注意力。
3. **检查生成**：集中查看故事承诺、人物目标、冲突、代价、关系、结局、必须保留、必须避免、作者补充和暂缓事项，确认后才点击“生成故事总纲”。

已有完整设定的项目可以从“直接检查设定”进入第三步；推荐路径的高完成度输入仍然跳过不必要的追问。保存草稿放在标题栏，底部只处理返回、暂时跳过、继续和生成。

## 保留的能力

- 原文事实、作者输入、确认方向、必须保留/避免和暂缓决定继续分开存储。
- 暂缓问题写入未决账本，`ai_permission` 保持 `none`，模型不能把它当成用户确认的事实。
- 候选请求失败时保留当前回答和备注，重试不会自动选中候选。
- 半轮答案、备注、自由输入可保存，刷新后恢复到对应问题。
- 生成请求只在第三步显式点击后发出；请求携带当前作者输入、原文约束和确认决定。
- 生成失败时内容不丢失，错误提示在当前视口顶部可见；继续完善会直接启动下一轮问题整理。
- 原生对话框、Escape、Tab焦点循环、手机窄屏布局和减少动画偏好继续生效。

## 实现

`frontend/lib/creation-setting-flow.ts` 提供步骤状态和未发送想法合并逻辑。`story-bible-panel.tsx` 负责步骤切换、显式生成门禁和持久化；`story-inspiration-editor.tsx` 负责单题确认；`creation-setting-summary.tsx` 负责检查页摘要。问题导航仍由 `storyInspirationRoundNavigation` 统一计算，避免“最后一题未答却无法继续”的分支重复。

本次没有改变后端模型协议、创作约束字段或总纲生成接口。生成会话与续写会话的保存、暂停、恢复由并行任务独立维护，详见文档67和56。
