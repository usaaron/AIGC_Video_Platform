# AI Comic Content OS 编剧质量审查（2026-09-06）

## 结论

项目已有检查漏场、漏字段、连续性和生成缩水的工程门禁，但尚未通过整部长篇样本证明这些风险已被全面解决。当前主链路仍然更像“结构化生产系统”，还不像“有个人判断的编导”。问题不在于有没有 Story Bible、剧情树或记忆，而在于这些产物目前主要记录“发生了什么”和“下一步做什么”，没有稳定记录“这个人为什么用这种方式做”“他会怎样误读别人”“这一场为什么必须以这种不体面的方式结束”。

因此，模型即使严格通过 schema 和连续性检查，也可能产出以下成品：

- 每集都有目标、冲突、回报、升级和钩子，但每集的戏剧动作可以互相替换；
- 人物状态账本很完整，人物说话、犹豫、撒谎和做选择的方式却没有个人纹理；
- 记忆包把事实带回来了，却把“人物已经怎样改变”压缩成一行摘要；
- 为了满足 25–35 句台词和 15–20 个动作单元，模型把一个真实动作拆成多个可计数动作；
- 路线图字段齐全，正文变成“把路线图翻译成对白”的说明稿。

当前最需要改变的是生产逻辑：结构字段负责防止漏项，编剧质量应该由“选择、代价、关系错位、信息不对称、场面独有的行为”负责。不要再让每个场景都执行同一个节奏公式。

## 本轮已落地的第一步

- 正文提示词不再要求每集固定执行“压力-行动-回报-升级”或“2至3次短循环”；现在要求至少产生一个有事件证据的不可逆变化，并允许关系转折、失败后果、信息交换、追逐/救援、延迟回报和安静余波等不同机制。
- `body_order` 仍保存真实表演顺序，但允许连续对白、动作段和有意义的沉默，避免机械的一动一说。
- 路线图提示词同步改为“每集选择适合人物和处境的戏剧机制”，相邻集要求机制有差异，不再要求重复同一循环。
- 阶段归一化的缺失字段不再静默写入“取得阶段性结果”“更高一级压力”等通用句，而是保留带阶段名称的 `待补充` 编辑占位；应急分解已调整戏剧职能标签。其他 fallback 路径仍需审查，尚不能视为通用默认叙事已全部消除。

这一步只改变提示词和缺失值的表达方式，没有放宽 75-115 秒、1-5 场、15-20 个动作单元、25-35 条对白的制作护栏；下一步再用受控样本验证这些护栏是否需要按节奏形态改成软目标。

## 已落地的第二步：可审阅的编导设计

路线图现已支持可选的 `dramatic_units` 和 `protagonist_cost`。作者可以编辑触发处境、人物做法、可见后果、变化类型、预期表演证据与个人代价，也可以删除或留空。新内容接入保存、局部修改、批准后的正文请求和 Markdown 导出；旧计划缺失字段仍可读取。

这一步采用“零最低数量、七项存储上限”，没有把最初设想的 3–7 个单位变成硬门槛。一个单位不等于一场戏或一次反转，代价也不必是惨烈损失：有依据的让步、承诺、丢面子或承担风险都可以。字段的作用是保存本集独有的行为设计，不能为填表新增故事事实。现有制作数量和 QC 门槛保持原口径；是否更像真人编导，仍需固定样本与真人盲评验证。

## 已经做对的部分

`frontend/lib/memory-recall.ts` 已经有 canonical / derived / provisional 层级、来源集数、场景证据、人物状态、知识状态、关系、支线、伏笔和追看点；这为人物连续性提供了正确骨架。

`backend/app/modules/script_engine/continuity_qc.py` 能检查死亡/复活、伤势和能力限制、知识分裂、故事线推进、追看点回应、setup/payoff 和支线场景证据。这些检查比单纯让模型“注意连续性”可靠得多。

`backend/app/modules/script_engine/prompt_builder.py` 已经明确要求动作可见、对白可表演、场景之间有因果、不得用空镜和复述凑量，也要求 `body_order` 保存真正的动作/对白交错顺序。这些是必要的交付护栏。

递归剧情树不强行平衡深度，叶节点根据内容决定是否进入 `episode_ready`；这是正确方向。路线图也已经要求每集具有独立因果贡献，而不是单纯把总纲按集切片。

## 按编剧流程逐层审查

### 1. 创作输入和 Story Bible

现在的输入识别能够识别 premise、story bible、episode plan、script，但“完成度”仍主要是材料数量和字段覆盖率。它不能判断作者输入里最有价值的东西是否是一个具体的观察、一个不寻常的关系、一个有代价的选择，还是一组市场套话。

Story Bible 目前适合做事实源，却不够像编剧室里的“创作宪法”。应补充以下内容，并且全部允许保持 unresolved：

- **人物的行为逻辑**：想得到什么、最怕失去什么、通常怎样达成目的、什么情况下会违背自己的习惯；
- **人物的错误方式**：他会怎样看错别人，错误会造成什么实际损失；
- **关系中的不对称**：谁更需要谁、谁掌握信息、谁有资格拒绝、谁在表面上占优；
- **本剧的独特观察**：本剧对职业、家庭、城市、权力或情感的具体观察，避免只写“爽、虐、反转、治愈”；
- **反套路边界**：哪些常见场面不能直接使用，若使用必须满足什么前置条件；
- **场面偏好**：允许沉默、误会、失败、错过、无效谈判和不完整胜利，而不是每集都必须把信息说清楚。

### 2. 剧情树

剧情树的结构校验很强，但现在仍把“转折点、事件链、选择后果、单元结算、交接压力”作为主要质量单位。它容易生成正确的故事运动，却不一定生成有辨识度的场面。

建议每个 `StoryPlanNode` 增加一个短的 `dramatic_signature`，不是口号，而是该段独有的戏剧机制，例如“所有人都知道门后有人，只有主角不知道谁在等她开门”或“主角赢得证据，却失去唯一能证明证据合法的人”。同时增加 `forbidden_shortcuts`，记录本段不能用的快捷解决方式：突然坦白、偶然监听、无代价打脸、反派自曝、配角替主角完成选择等。

### 3. Episode Roadmap

`EpisodePlanGenerationItem` 在 `backend/app/modules/script_engine/long_story_models.py` 中为 `stage_opposition`、`episode_payoff`、`pressure_escalation` 提供了通用默认值：

```text
承接当前阶段的具体阻力。
兑现一个可见的阶段推进结果。
当前结果引出更高一级的因果压力。
```

这些默认值对旧 payload 兼容有用，但对新生成是危险的。它们会让空字段看起来合法，并把系统套话送进路线图与正文提示词。新版本应把这三个字段设为 nullable 或在新 schema 中设为必填；旧版本只在明确标记为 legacy 时兼容，并在 UI 中显示“来源缺失”，不能把默认句当作内容。

路线图还应增加以下内容，而不是继续增加抽象字段：

- `episode_dramatic_question`：观众在本集真正想知道什么；
- `protagonist_misread`：主角本集对人或局势的一个具体误判；
- `irreversible_cost`：本集结束后无法恢复的损失；
- `relationship_event`：关系发生了什么可观察变化；
- `scene_engine`：本集的主要场面机制，如交易、逼供、照料、跟踪、公开表演、共同撒谎、错认或被迫合作；
- `anti_formula_note`：本集明确不能用的常规处理；
- `quiet_beat_allowed`：允许哪一处不靠升级而靠停顿、回避或误读制造压力。

这些字段不应全部交给模型自由填写。可以由模型建议、作者确认，且每集只保留一两个真正重要的创作判断。

另一个必须先解决的产品一致性问题是容量口径：当前创建页实际开放的是 80,000–200,000 字三个档位，默认 140,000；后端 `StoryProject` 的 450,000 默认值属于兼容合同，600,000 是隔离容量验收目标，README 的 400,000–500,000 字是历史产品设想。它们不能同时被描述为当前生产能力。现阶段先在文档和验收记录中明确三者边界，后续若要开放更大 UI 档位，再单独修改前后端合同并补真实验收。

### 4. 正文生成

`prompt_builder.py` 的中国大陆正文合同目前出现了明显的“提示词腔”：要求持续执行“压力-行动-回报-升级循环”，通常安排“2至3次短循环”，并把场景、镜头、对白、body_order、状态账本、追看点和时长规则集中写入一段超长指令。模型会优先完成可数的格式任务，牺牲停顿、含混、尴尬、意外和独特行为。

建议把生成拆成两个内部阶段：

1. **场面设计阶段**：只决定本集每场的关系目标、信息差、行为选择、失败方式和不可逆变化，不写完整台词；
2. **正文实现阶段**：把场面设计写成可拍正文，只接收本场需要的约束，不再重复整套总规则。

提示词中的节奏要求应改成“本集必须产生若干个不可逆变化，但变化的形态由本集的场面机制决定”，不要明示每集必须有 2–3 个相同结构的循环。至少允许以下节奏形态：

- 一场持续谈判，信息优势在同一空间内多次换手；
- 两场对照剪辑，观众知道两边在误解彼此；
- 一次行动不断失败，但失败改变关系而不是升级敌人；
- 看似没有推进的一场照料、等待或收拾残局，最后暴露人物真正选择；
- 主角完成目标，却以错误方式完成，下一集承接的是道德或关系代价；
- 本集只解决一个问题，但让另一个问题变得不可再回避。

模型可以获得一个“本集节奏形态”枚举，但应由路线图/作者选择，不能默认 `pressure_action_payoff_escalation`。

### 5. 记忆系统

当前记忆系统更像“事实检索包”，还不是“人物记忆”。`characterCapsules` 主要带回 currentGoal、emotionalState、lifeStatus、location、activeConstraints、latestChangeSummary、knowledge；`storyLineCapsules` 主要带回当前状态和下一步；`roadmapCapsules` 主要带回出口、升级压力和下一集义务。

这能防止前后矛盾，却不能让人物活起来。建议把记忆分成三种不同用途：

- **世界事实记忆**：不能错的客观状态，如伤势、物品、位置、权限、已知/未知信息；
- **人物倾向记忆**：这个人惯用的回避方式、谈判习惯、说谎策略、羞耻触发点、对某人的特殊称呼、会做但不承认的事；
- **本集戏剧记忆**：最近一次选择留下的心理债、关系债、未说出口的话、错误解释和下一次必须面对的后果。

人物倾向不能由模型在每集自由重写。应记录为带证据的累积观察，例如“遇到被质疑时先纠正细节，不先回答核心问题（第2、5集）”。每次正文生成最多注入 2–4 条与本集相关的倾向，避免把人物卡变成长篇百科。

记忆选择也不应只靠 priority 和字符预算。应先按当前场景的冲突、出场人物、计划故事线和本集机制筛选，再按“会改变本场选择”的因果相关性排序。一个不相关但高 priority 的旧事实，不应挤掉一个低 priority 但直接影响主角本集误判的关系记录。

### 6. QC 和修改

当前 QC 更擅长检查结构、因果、连续性和可解释性，不能可靠识别“句子都对但像模板”的问题。需要增加两类审查：

- **场面独特性**：本集最关键的行为是否只能发生在本剧人物身上；删除人物姓名后，场面是否仍可被任何短剧替换；
- **表达重复性**：与最近 5–10 集的开场方式、冲突启动、反派出场、揭示方式、尾钩语义和对白动作组合做相似度检查。

重复检查不能只做字符串相似度。应把每场编码为 `scene_engine + information_shift + relationship_shift + cost_type + ending_mode`，检查连续集是否重复同一组合。发现重复时，修改器应优先换“场面机制”和“人物选择”，而不是换几个形容词。

建议新增一个非阻断但可见的 `formula_risk_report`，输出：

- 最近 N 集重复的场面机制；
- 重复的开场动作和尾钩动作；
- 连续使用的冲突词和结尾句式；
- 本集是否只有“发现/追查/对峙/揭露”而没有关系或代价变化；
- 本集最像哪几集，以及相似原因。

这类报告先作为编剧审阅信号，不直接把所有非典型写法判错。

还要审查失败保底路径。`story_planning_service.py` 在若干规划失败或字段缺失时会拼接“推进当前阶段冲突并迫使主角作出选择”“取得阶段性结果并承担明确代价”等万能句。它们对程序是合法字符串，对编剧是没有事件内容的空壳；一旦进入路线图，就会被正文模型当成事实继续扩写。失败应进入 `review_required/blocked`，显示缺失字段，让作者补写或重新生成，不能把模板句保存成规划事实。

`episode_layer_contracts.py` 的部分 progression 指标按 decision/reveal/payoff/pressure/exit 等字段去重计数，而不是验证正文里发生了几次可见变化。模型填入几句不同的抽象话也可能造成“因果齐全”的假象。字段计数应降为诊断，真正的变化证据要绑定到具体 `scenes.character_actions` 和对白行为。

## 对场景数、对白数和镜头数的判断

你的限制思路是合理的：大模型在长输出后段会缩水，固定下限是工程上有效的护栏。问题在于当前限制同时被当作“生产合同、路线图预算、模型提示和验收门槛”，容易造成模型为了数字写作。

当前值 `75–115 秒、1–5 场、25–35 句台词、15–20 个动作单元` 可以保留为**硬边界/异常报警**，不应继续作为每集的默认目标。尤其不建议所有集都默认 30 句对白、16 个动作、3 场戏。

更合适的方案是：

### A. 先算“有效戏剧单位”，再映射到制作单位

按本集已有事件记录 `dramatic_units`，每个单位包括触发、人物选择、可见后果和变化类型。初始设想的 3–7 个只保留为后续样本观察假设；当前实现不设最低数量，最多 7 项只是存储边界。单位数量不等于场景数，也不等于台词数，不能拿数量替代戏剧价值。

然后由运行时根据时长和场面机制生成软目标：

| 集类型 | 建议场景 | 台词软目标 | 动作单元软目标 |
|---|---:|---:|---:|
| 单一密闭场谈判/审讯 | 1–2 | 12–26 | 8–16 |
| 常规推进集 | 2–4 | 18–32 | 12–20 |
| 追逐/救援/公开事件 | 3–5 | 10–28 | 16–28 |
| 关系转折/沉默高压集 | 1–3 | 8–22 | 8–18 |
| 季终/剧终 | 2–5 | 按收束需要 | 按收束需要 |

这些是软目标区间，不是让模型选择一个固定数字填满。硬边界只负责拦截明显缩水或超时。

### B. 用分段预算防止后段缩水

不要只在整集结束检查总数。把每集分成 opening / complication / decision / exit 四个功能段，为每段设最小“变化证据”，而不是最小台词数。例如：

- opening：前 15–20 秒内出现具体异常或关系动作；
- complication：至少一次计划失败、误判或信息差变化；
- decision：主角做一个不可由别人代替的选择；
- exit：选择留下可验证的代价、关系变化或新义务。

这样可以防止模型写满 30 句却把真正的决定放在最后两句。

### C. 对白使用“功能覆盖”而不是句数

验收时统计每句对白承担的功能：请求、拒绝、试探、撒谎、纠正、威胁、讨价、转移、承认、误解、沉默/未说出口等。连续 4 句只承担同一种功能，应触发修改建议。台词少但每句改变关系的集，可以通过；台词多但只是解释路线图的集，不应通过。

### D. 动作单元按事件边界计数

当前 `character_actions` 的 15–20 项很容易被拆成“抬眼、握紧、转身、迈步”四项。应要求一个动作单元至少造成一个可观察结果或改变一个空间/道具/关系状态；单纯表演连续动作在内部合并。镜头数量交给拍摄阶段估算，编剧阶段只保留 `observable_action_units`。

## 反 AI 味的生成策略

### 1. 先给本集一个“限制条件”，再给剧情任务

比“写一个反转”更有效的是给一个场面限制：不能直接问、不能离开现场、必须保护某个不知情的人、只能用一个道具传递信息、双方都不能说出真正目的。限制会迫使模型产生具体行为，减少万能对峙。

### 2. 强制人物选择带有个人代价

路线图的 `protagonist_decision` 不只写“决定调查/反击/隐瞒”，而要写“他为了保住什么，主动牺牲了什么”。人物记忆中保存这个代价，下一集先处理代价，再处理新事件。

### 3. 使用“误读—修正—余波”而不是“揭露—升级—钩子”

很多真人编导的戏剧张力来自人物对彼此的错误解释。每集可以要求一个可选误读，但不要求每集都反转。误读必须导致行动或关系变化，不能只写在 ledger 里。

### 4. 为模型提供少量反例，而不是长篇禁令

在每个市场/类型知识包中，增加 5–10 个短的“坏例→为什么假→如何改成具体行为”，例如：

```text
假：他冷冷一笑，事情变得更复杂。
改：他把对方递来的合同翻到最后一页，指出签名日期早于事故三天；随后把合同推回去，没有问是谁伪造的。
```

反例要描述行为机制，不能复制成固定句式。提示词中只注入与当前类型和场面机制相关的 1–2 条。

### 5. 修改器优先改行为，不优先改文风

当 QC 发现 AI 味时，修改顺序应是：重复场面机制 → 无个人代价 → 信息说得过于完整 → 关系没有变化 → 台词句式重复 → 最后才是形容词和语言润色。现在的修改路径更容易在结构合法后做局部补丁，补丁会把模板味保留下来。

### 6. 保留一小块受控的创作自由

目前正文合同要求严格按 `scene_execution_plan` 的场景标题、人物范围、目标、行动、转折和退出状态扩写，结构本身若已俗套，后面的 Deepening 也只能在原结构内润色。建议每集给模型 1–2 个低风险创作槽位：一个非关键道具用法、一个人物微习惯、一个不改变事实的空间调度或一句带个人语域的表达。槽位必须标明 `provisional`，不能改变死亡、身份、关系结果、关键秘密和结局，但能让正文不只是把路线图翻译成台词。

## 建议的实施顺序

### P0：先解决会直接污染成品的地方

1. [已局部落地] 缺失阶段字段现在保留带阶段名称的 `待补充` 编辑占位，旧 payload 仍走兼容归一化；其他规划和分场 fallback 的通用叙事值仍需继续清理。
2. [已完成第一步] 把正文和路线图提示词中的固定压力—行动—回报—升级循环改为可选择的节奏形态，默认不指定。
3. [已实现，待真实内容验收] 增加 `dramatic_units` 和 `protagonist_cost`，已接路线图编辑、保存、局部修改、导出和批准后的正文上下文；字段可选，不扩大批准门槛。
4. [后端与 Workspace UI 第一版已实现，待样本校准] `episode_quality_review.v1` 已在生成完成和人工复审后写入 Draft `llm_metadata`：保留既有总量硬边界报警，记录有限关键词对白功能覆盖并提示连续四句同功能，按真实 `body_order` 给出 opening / complication / decision / exit 四段位置型变化候选，同时检查可选戏剧单位和人物代价的正文证据。规划摘要不能充当正文证据，人物选择和可见后果必须命中不同正文条目；所有命中都明确不是语义证明，且不扩大批准、保存或 Finalization 门槛。Workspace 可折叠面板显示摘要和完整诊断，正文直接编辑时标记待刷新，手动保存前通过现有复审接口重算报告。已加入五种节奏形态的固定计数样本基线，当前只验证报告稳定输出和硬边界仍为非阻断诊断；真人盲评和软目标误报校准仍未完成。
5. [口径已澄清] 当前 UI 生产档位为 80,000–200,000 字、默认 140,000；450,000 是后端兼容默认值，600,000 是隔离容量验收目标，400,000–500,000 是历史产品设想。真人盲评与 600,000 字端到端生产验收仍未完成。

### P1：让记忆真正服务人物

1. 增加带场景证据的 `behavioral_tendencies`、`misread_patterns`、`speech_rituals`、`relationship_debts`。
2. 记忆检索先按本集冲突和出场人物过滤，再按因果相关性排序。
3. 每集生成后从已确认正文提取 0–2 条新的人物行为观察，暂存为 provisional，经作者确认后进入 canonical。

### P2：建立反套路质量回路

1. 建立 20–30 集固定 fixture，覆盖密闭谈判、追逐、关系转折、失败集、季终等不同节奏形态。
2. 对每集保存 `scene_engine`、`information_shift`、`relationship_shift`、`cost_type`，生成相似度和公式风险报告。
3. 评审指标增加“可替换性”：把人物名和专有名词遮掉后，编剧能否从行为逻辑认出这是本剧。
4. 让真人编导每轮盲评“像模板/像真人/人物是否会这样做/是否愿意继续看”，不要只看 schema 通过率。

## 最终判断

当前项目已为漏写、缩水、遗忘前情和越过作者决定建立防护，但工程合同通过还不能回答“为什么这场戏只能由这个人以这种方式发生”。

你设定场景数和对白数的出发点是对的，但应把它们降为制作护栏，把核心质量转移到戏剧单位、个人代价、信息错位、关系事件和分段变化证据上。这样既能对抗模型后段缩水，也不会把每一集压成同一个节拍模板。
