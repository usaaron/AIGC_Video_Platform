# Gemini 数量修复与内容保留

日期：2026-09-11。对应升级计划第一步；下一步是双市场完整流程与连续三集验收。

## 结论

已定位并修复当前 Gemini 3.6 Flash 网关的嵌套结构兼容问题。同一隔离故事、同一数量缺口、同一提示词，在展开嵌套 JSON Schema 引用后返回完整补丁，通过 3 场、25 条双语对白、15 项动作和预计 103 秒时长的检查。没有降低数量、语言或时长门槛。

此前 `overseas-market-bound` 失败只保存了计数与请求日志，没有原始正文和补丁，因此无法证明本次与那次失败具有完全相同的原因。本次使用固定虚构故事的新样本，主动把 30 条双语对白减为 21 条，再验证同一数量修复路径；这是有来源记录的故障注入，不是历史响应的精确复现。

## 发现与修改

- 网关两轮修复、共四次 HTTP 200 返回中，只含第一场及空对白对象。后两次同时保存了解析前原始文本，证明空对象来自上游返回，而不是本地解析丢失字段。
- 原请求只展开根层场景数组，嵌套 `DialogueLine` 仍为 `$ref`。现在 Gemini 路径展开非递归引用，保留 required、长度、枚举、双语和禁止额外字段等约束；递归或未知引用保留原生 schema。其他模型沿用原有处理。
- 同输入对照的真实修复在一个补丁回合内通过：一次连接失败后传输重试成功，实际两次请求，合计约 21.45 秒。该证据支持当前网关的嵌套引用兼容性诊断，不代表所有 Gemini 接口都不支持引用。[Google 官方结构化输出文档](https://ai.google.dev/gemini-api/docs/structured-output) 与具体第三方网关的转换行为应分别验证。
- 合并动作和对白的两套本地数量调整循环。只按明确句界拆分；不在词中间断开，不删除短对白，不跨中间动作合并台词，不丢失或复制双语译文，并随数组变化更新 `body_order`。没有安全调整方式时保留正文并进入有界修复或明确失败。
- 修复重试提示不再假定数量已经正确，而是反馈实际校验错误。最终本地兜底也必须满足时长要求，不能放行数量合格但时长越界的补丁。
- 独立探针新增输入、补丁、解析前返回和结果留档，以及零 HTTP 离线重放。产品日志没有新增正文留档。固定测试素材保存于 `tests/fixtures/production_count_repair/gemini_shortfall.v1.json`，不含凭据、用户项目或运行 ID。
